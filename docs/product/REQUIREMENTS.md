| 项 | 内容 |
|---|---|
| 版本 | 1.0（2026-11-14） |
| 状态 | 已确认，作为 M0–M5 的范围基线 |
| 配套 | [架构设计文档](../architecture/ARCHITECTURE.md)、[ADR](../adr/README.md) |

## 1. 产品愿景

PiArc 是面向专业开发者的 AI 编码 Agent 桌面应用：**Claude Code 的 Harness 专业度 + Pi 的多模型能力 + 原生桌面体验**。用户可以用任意主流模型服务商，在一个响应迅速、资源占用稳定的原生应用里，完成"理解代码 → 规划 → 修改 → 验证 → 审阅 → 回退"的完整开发循环；已有的 Claude Code 配置（memory、权限、hooks、agents、skills、MCP）可以直接带过来使用。

## 2. 目标用户

| 用户 | 特征 | 核心诉求 |
|---|---|---|
| 专业开发者（主要） | 日常用 AI agent 写代码，在意可控性与效率 | 审批可控、改动可审阅可回退、长会话不卡、多会话并行 |
| 多模型用户 | 同时使用 Claude、GPT、Gemini、DeepSeek、Kimi、Qwen、本地模型等 | 一个工具里切换模型，Harness 体验一致；按任务选择性价比合适的模型 |
| Claude Code 迁移用户 | 已有 `.claude/` 配置与工作流 | 零配置迁移；用其他模型跑现有的 agents、skills、hooks |
| 团队与企业（后续） | 需要统一策略与审计 | 托管配置、权限白名单、审计记录 |

## 3. 核心场景

| 编号 | 场景 | 期望 |
|---|---|---|
| S1 | 打开一个仓库，让 agent 修复一个失败的测试 | agent 读代码、改代码、跑测试；每次写文件和执行命令按权限模式审批；改动在 Changes 面板可逐文件审阅 |
| S2 | 大改动前先规划 | 进入计划模式，agent 只读探索后提交计划；用户评论、修改、批准后自动执行；执行过程有任务清单 |
| S3 | 同时推进三件事 | 三个会话并行（可各自在独立 worktree），侧栏显示状态，需要审批时收到通知，不卡顿 |
| S4 | 改坏了，回到之前 | 选择某条用户消息，回退代码、对话或两者；冲突时给出明确提示 |
| S5 | 探索陌生代码库 | 主会话派出只读的探索子 agent（可指定便宜快速的模型），并行搜索后汇总 |
| S6 | 接入团队的工具 | 配置 MCP server（stdio 或 HTTP + OAuth），工作区内所有会话共享连接 |
| S7 | 迁移 Claude Code 配置 | 打开带 `.claude/` 的仓库，memory、权限规则、hooks、agents、skills、commands 自动生效，配置诊断页列出生效与忽略项 |
| S8 | 跑长任务 | 后台运行开发服务器或长构建，agent 继续工作，任务完成后自动通知 agent |
| S9 | 切换模型 | 会话中途从一个服务商切到另一个，提示缓存失效等代价后切换，会话继续 |

## 4. 功能需求

优先级：**P0** 首个可用版本必须具备；**P1** Beta 前完成；**P2** Beta 之后。里程碑定义见架构文档第 16 章。

### 4.1 工作区与会话

| 编号 | 需求 | 优先级 | 里程碑 |
|---|---|---|---|

| FR-WS-02 | 侧栏按工作区分组列出会话，显示状态徽标（错误 > 等待审批 > 运行中 > 未读 > 空闲） | P0 | M1 |
| FR-WS-03 | 新建、重命名、置顶、归档、删除会话；会话持久化，重启应用后可恢复 | P0 | M1 |

## 5. 非功能需求

| 编号 | 类别 | 要求 |
|---|---|---|
| NFR-01 | 性能 | 满足架构文档第 11 章的全部预算，作为发布门槛 |
| NFR-02 | 可靠性 | Agent Host 崩溃后 3 秒内自动恢复会话；进行中请求标记为状态未知，不静默丢失 |
| NFR-03 | 安全 | 默认手动审批；项目信任闸门；凭据只存钥匙串；威胁模型（架构文档 10.1）逐条有对策与测试 |
| NFR-04 | 隐私 | 会话数据只在本机；遥测默认关闭且不含内容 |
| NFR-05 | 合规 | 不提供 Claude 订阅登录；clean-room；自有品牌（ADR-0006） |
| NFR-06 | 无障碍 | VoiceOver 可用；全部功能可只用键盘完成；遵循减少动态效果与高对比度设置 |
| NFR-07 | 本地化 | 简体中文与英文 |
| NFR-08 | 平台 | macOS 26+，Apple silicon 为主，Intel 单独提供；Windows 见架构文档第 15 章 |
| NFR-09 | 可移植性 | Core 与 Agent Host 不含 macOS 专属假设，CI 在 Windows 上构建 Core |
| NFR-10 | 可维护性 | 跨进程接口有 schema 与契约测试；Pi 升级流程可重复（架构文档 5.7） |

## 6. 范围外

- 通用知识工作助手（Chat / Cowork 类形态）、Artifacts 发布服务；
- 云端托管会话、Remote Control、手机端；
- IDE 插件与行内代码补全；
- 插件市场托管服务；
- Mac App Store 版本；
- 第一版的 Windows 客户端。

## 8. 验收方式

- 每条功能需求在实现时登记到能力清单（`tests/capabilities.yaml`），至少有一个 L2 场景覆盖；完成状态由测试结果自动生成。
- 涉及 UI 的需求另有 XCUITest 流程测试或快照测试，并在本地以测试账号实际操作验证。
- 非功能需求按架构文档第 11 章的测量方式进入 CI。
