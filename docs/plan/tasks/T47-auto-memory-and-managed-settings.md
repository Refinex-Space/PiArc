## 背景与目标

本任务做两件互相独立、但都改变"配置与上下文从哪里来"的事：

- **自动记忆**：agent 自己维护的跨会话笔记（架构第 6.6.2 节末条）。它会在每个新会话开头进入上下文，所以它既是便利，也是提示注入的持久化通道：一次被诱导写下的"记忆"会影响之后所有会话。
- **企业托管配置**：组织下发、优先级最高、用户与项目都不能覆盖的设置（ADR-0005 合并顺序的第一位，第 6.2.3 节裁决第 1 步）。前面的任务已为它预留了入口：裁决流水线的企业 deny、MCP 与插件的企业来源、配置诊断的企业来源、沙箱的企业网络白名单。

两者都牵涉存储位置、平台差异和安全边界，先写设计增补交用户确认，再实现。完成后，自动记忆可见、可编辑、可关闭；托管配置能从文件与系统策略读取，兼容读取 Claude Code 的托管文件，并支持"只允许托管 hooks"。

## 交付物

### 设计增补（关口前）

### 1. `docs/architecture/addenda/T47-auto-memory-and-managed-settings.md`

| 部分 | 必须回答的问题 |
|---|---|
| 记忆存储 | 位置（PiArc 数据目录下，按仓库主 checkout 归属，worktree 共享）；索引文件与主题文件的格式与大小上限；是否只读导入 Claude Code 的 `~/.claude/projects/<项目>/memory/` |
| 记忆写入 | agent 用专门的宿主工具还是受限的文件工具写入；写入经 Core（审计、路径边界豁免的范围）；是否需要审批；项目未信任时是否允许写入 |
| 记忆注入 | 新会话把索引的前多少行或字节放进 system prompt 第 4 段；主题文件按需读取；压缩后重注入；会话中途变化以追加消息送达 |
| 用户可见性 | transcript 中"已保存 / 已调用记忆"的提示；设置中浏览、编辑、删除；用户级与项目级开关；内置命令入口 |
| 托管格式 | PiArc 自有托管文件的名称、目录（macOS 与 Windows 的系统级位置）、片段目录与合并规则；支持的键与"仅托管可设置"的键清单，至少含"只允许托管 hooks"；候选键（只允许托管权限规则、只允许托管 MCP server、沙箱只用托管域名、禁用 Auto 模式）逐个给出是否纳入第一版 |
| 交付方式 | 文件、macOS 配置描述文件（偏好域与 D2 的应用标识对应）、Windows `HKLM` 策略键；哪些位置算"管理员来源"（用户可写的位置如 `HKCU` 不获得托管优先级）；多来源同时存在时取其一还是合并 |
| Claude Code 兼容 | 读取 Claude Code 的 `managed-settings.json`、`managed-settings.d/` 等托管文件（只读）；是否同时读取它的 MDM 偏好域与注册表键、托管 CLAUDE.md；不支持的键在诊断中标为"已忽略" |
| 异常与变更 | 托管文件格式错误时的行为（继续运行并告警，还是拒绝启动）；文件与策略变化的检测方式与频率；`ConfigChange` hook 对托管来源不可阻断 |

增补末尾单列"需要用户确认的要点"，至少包括：记忆写入是否需要审批、未信任项目的记忆策略、第一版支持的托管专属键、管理员来源的判定、托管文件格式错误时的行为、是否读取 Claude Code 的 MDM 与注册表来源。

### 实现（关口后）

### 2. 自动记忆

- 存储与写入按增补实现，写入经 Core 并进入审计；worktree 共享、不同仓库隔离。
- 注入：Harness Kit 在组装第 4 段时加入索引；T27 的压缩后重注入列表加入自动记忆。
- 客户端：transcript 提示、设置中的记忆页（浏览、编辑、删除、开关）、内置命令入口。关闭后不注入，写入工具对模型不可见。

### 3. 托管配置（piarc-config 与平台适配层）

- 托管来源作为最高优先级层接入 ADR-0005 的合并顺序：标量键不可被覆盖，列表键合并，deny 永远优先。
- 平台读取放在 Core 的平台适配实现中：macOS 托管偏好、Windows 注册表、两平台的系统级托管文件。根路径与注册表键可注入，测试不写系统目录、不写 `HKLM`。
- "只允许托管 hooks"：开启后 piarc-hooks 只执行托管来源的 hooks，跳过的 hooks 写入审计。
- 把增补纳入的其他托管专属键接到已有的预留入口（MCP、插件、沙箱、权限、Auto 模式）。
- 配置诊断显示托管来源的加载状态、生效键与忽略键；设置界面中被托管锁定的项显示锁定标识且不可编辑。

### 4. L2 场景与能力 ID

- `tests/scenarios/memory-auto-*.yaml`、`tests/scenarios/managed-*.yaml`，能力 ID 例如 `CAP-CX-AUTOMEM-001`、`CAP-CFG-MANAGED-001`。
- Claude Code 托管文件的夹具按 macOS 与 Windows 两套路径布局准备，通过注入的根路径加载。

## 实现要点

- 记忆内容是会持续生效的指令：注入时标注来源，审计中能查到每条记忆由哪个会话写入。
- 托管优先级的测试写成矩阵：同一键分别在会话、项目、用户、托管层设置，断言托管值胜出。
- 跨平台：路径比较先规范化（第 15.3 节）；Windows 注册表读取只在 Windows 编译，CI 在 Windows runner 上跑对应测试。

## 验收标准

- [T47-A01] 设计增补覆盖记忆存储、记忆写入、记忆注入、用户可见性、托管格式、交付方式、Claude Code 兼容、异常与变更八部分，并列出需要确认的要点；用户已确认。验证：增补文件与用户确认记录。
- [T47-A02] agent 写入记忆后，索引与主题文件出现在增补规定的位置，审计记录写入会话，transcript 显示"已保存记忆"。验证：L2 场景与 Playwright。
- [T47-A03] 新会话的 system prompt 第 4 段包含索引且遵守长度上限，主题文件只在读取后进入上下文；压缩后的请求重新包含索引。验证：mock provider 请求断言。
- [T47-A04] 同一仓库的不同 worktree 共享记忆，不同仓库互相隔离。验证：测试。
- [T47-A05] 用户可在设置中浏览、编辑、删除记忆；关闭自动记忆后，请求中不含记忆，写入工具不出现在工具列表中。验证：Playwright 与 mock provider 请求断言。
- [T47-A06] 记忆的读写与导入过程中，`.claude/` 与 `~/.claude/` 下没有任何写入。验证：测试。
- [T47-A07] 托管层的值在会话、项目、用户各层同时设置同一键时胜出；列表键合并且托管 deny 生效。验证：测试矩阵。
- [T47-A08] 开启"只允许托管 hooks"后，用户、项目与插件的 hooks 不执行且写入审计，托管 hooks 照常执行。验证：L2 场景。
- [T47-A09] 增补定义为"非管理员来源"的位置中的配置不获得托管优先级。验证：测试。
- [T47-A10] Claude Code 托管文件（macOS 与 Windows 两套路径布局的夹具）被读取，支持的键生效，其余键在配置诊断中列为"已忽略"。验证：测试与 Playwright 截图。
- [T47-A11] 托管文件格式错误时按增补规定处理；托管配置变化后在增补规定的时间内生效，且 `ConfigChange` hook 不能阻断托管来源的变化。验证：测试。
- [T47-A12] 设置界面中被托管锁定的项显示锁定标识且不可编辑。验证：Playwright 与截图（`tmp/evidence/T47/`）。
- [T47-A13] `npm run verify` 通过（含 Windows CI 上的注册表读取测试）。验证：命令输出。
