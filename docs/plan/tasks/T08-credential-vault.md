## 背景与目标

ADR-0018 第 5 条决定用凭据保险箱：服务商 API key、OAuth token、MCP token 加密存放在数据目录下的 `secrets.vault`（AES-256-GCM），系统凭据库只存一个主密钥。这样 ad-hoc 签名的应用每次更新后最多弹一次钥匙串授权，Windows 也绕开了凭据管理器单条 2,560 字节的上限。凭据只经 AHP 传给 Agent Host，不进环境变量（第 5.4 节）。

S5 验证两件事：保险箱本身的正确性与安全性；它与 Pi 凭据接口的适配。Pi 的凭据接口是同步语义，系统凭据库访问是异步的（风险 R11）。第 5.4 节的方案是 Agent Host 启动时一次性取回凭据放在内存，写操作异步回写 Core。

通过标准（架构第 16 章）：登录、刷新 token、多会话读取正常；磁盘上无明文；macOS 未签名构建更新后最多弹一次钥匙串授权。最后一项需要两次打包构建，由 T12 测量；Windows 凭据管理器的实机结论在 W0。

## 交付物

### 1. 保险箱文件

- 格式：魔数 + 格式版本 + 主密钥标识 + nonce + 密文 + 认证标签；头部作为 AEAD 附加数据参与认证；每次写入用新的随机 nonce。
- 明文是"凭据键 → 值与元数据"的结构，键形如 `provider/<id>`、`oauth/<id>`，预留 `mcp/<server>`。
- 写入用同目录临时文件加原子 rename，失败时旧文件保持完整。
- 内存中的明文与主密钥用后清零；日志与错误信息不含凭据值。

### 2. 主密钥

- 32 字节随机数，经 keyring-core 存入系统凭据库（macOS 钥匙串、Windows 凭据管理器）。服务名以应用标识（D2）为前缀，从集中定义的应用标识读取。
- 经 `SecretStore` 窄 trait 访问（第 7.1 节），测试用内存实现与可注入错误的替身。
- macOS 不启用 data protection keychain：它的 access group 需要 provisioning profile 授权，ad-hoc 签名的构建没有（native-stack.md 第 8.4 节）。使用登录钥匙串，选择与理由写进报告。
- 状态与行为：

| 情况 | 行为 |
|---|---|
| 没有保险箱、没有主密钥 | 首次创建：生成主密钥、写入凭据库、创建空保险箱 |
| 有保险箱、主密钥可用 | 正常读写 |
| 有保险箱、主密钥缺失 | 结构化错误（主密钥丢失）；不新建主密钥，不覆盖保险箱 |
| 主密钥访问被拒绝、凭据库锁定或不可用 | 结构化错误（可重试），提示重新授权；不回退明文 |
| 保险箱被篡改或格式版本未知 | 结构化错误（完整性或版本）；不返回任何部分数据 |

### 3. AHP 与适配层

- 在 `piarc-protocol` 中定义 `secrets/get`、`secrets/set`、`secrets/delete`，以及启动时一次取回全部凭据所需的方法，走 T02 的生成流程并补样本。Core 侧失败时会话报错，不回退明文（第 7.4 节）。
- Agent Host 适配层（`agent-host/src/runtime/`）实现 Pi 要求的凭据接口：
  - 启动时一次性从 Core 取回凭据放在内存；
  - 读操作同步返回内存中的值；写操作先更新内存，再异步回写 Core，回写失败时上报会话错误；
  - 满足 Pi 对修改串行化的要求（同一 provider 的修改串行）。
- 多个 Agent Host（多个工作区）同时缓存凭据时，Core 是唯一写入方。一处写入后其他 Agent Host 的缓存如何更新（例如 Core 推送变更通知）、两处同时刷新同一 token 如何避免互相覆盖，给出方案并测试，写进报告。
- 凭据不经环境变量传给 Agent Host 及其子进程。

### 4. 登录与刷新的 mock 验证

- 用一个测试 provider（或 mock 授权端点）模拟：登录后写入凭据；token 剩余有效期低于 pi-ai 的刷新阈值时触发刷新，新 token 经适配层回写 Core。
- 不使用、不启用 Anthropic 订阅 OAuth（ADR-0006）。

### 5. S5 报告

`docs/spikes/S05-credential-vault.md`：文件格式、密钥管理、适配层与缓存一致性方案、测试结果、结论。macOS 已验证：钥匙串中主密钥的创建、读取、删除与错误路径，适配层与无明文扫描；待 W0：Windows 凭据管理器实机与 Windows 数据目录扫描；待 T12：两次构建之间的钥匙串弹窗次数。更新 `docs/spikes/README.md`。

## 实现要点

- 测试只在测试专用的服务名下创建凭据库条目，结束时清理；不读写用户已有的条目（协议"安全与不可逆操作"）。
- 真实凭据库的集成测试单独成组：macOS 本机必须运行并记录结果；CI 上凭据库不可用时显式报告原因，不静默通过（第 12.6 节）。Windows 代码路径在 Windows CI 上编译并跑替身测试。
- 加密库与 keyring store crate 的选型是补充型决策，经 cargo-deny 检查。
- 无明文扫描用测试生成的随机凭据值，在数据目录、日志、会话临时目录、系统临时目录中逐字节搜索；同时检查 `pi/` 下没有 `auth.json`、`mcp-auth.json`。
- 查询钥匙串条目时只确认存在与否，不输出密码（协议禁止打印凭据）。

## 验收标准

- [T08-A01] 加解密往返正确；篡改保险箱头部、nonce、密文或标签中任一字节后读取失败，返回完整性错误且不返回任何凭据。验证：单元测试。
- [T08-A02] 格式版本未知的保险箱返回版本错误。验证：单元测试。
- [T08-A03] 首次运行创建主密钥与空保险箱；保险箱存在而主密钥缺失时返回"主密钥丢失"错误，不新建主密钥，保险箱文件哈希不变。验证：测试。
- [T08-A04] 主密钥访问被拒绝、凭据库锁定或不可用时返回带 `retryable` 的结构化错误，数据目录中不出现任何明文文件。验证：替身注入测试。
- [T08-A05] 写入过程中模拟失败，旧保险箱保持完整且可读。验证：测试。
- [T08-A06] `secrets/*` 消息有 schema 与 golden 样本；Core 侧失败时 Agent Host 报会话错误，不回退明文。验证：契约测试与集成测试。
- [T08-A07] 适配层满足 Pi 凭据接口的契约：同步读、同一 provider 的修改串行、写入异步回写 Core。验证：针对 Pi 接口契约的测试（Pi 锁定版本有现成测试时复用）。
- [T08-A08] 模拟登录写入凭据；token 临近过期时触发刷新，新 token 回写 Core 后，保险箱与各会话读到的值一致。验证：mock 测试。
- [T08-A09] 同一 Agent Host 的多个会话并发读写、两个 Agent Host 同时写同一凭据，结束后保险箱内容一致，没有丢失的更新。验证：并发测试。
- [T08-A10] 数据目录、日志、临时目录中搜不到测试凭据的明文；`pi/` 下没有 `auth.json`、`mcp-auth.json`；Agent Host 及其子进程的环境变量中没有凭据。验证：扫描测试输出。
- [T08-A11] macOS 钥匙串集成测试在测试服务名下创建、读取、删除主密钥，结束后无残留条目。验证：本机测试输出与条目存在性查询结果。
- [T08-A12] 正式构建的凭据库服务名以 D2 的应用标识为前缀。验证：代码检查与测试；D2 未落实时标 `blocked`。
- [T08-A13] S5 报告（macOS 部分）已写入，列出待 W0 与待 T12 的项，`docs/spikes/README.md` 已更新。验证：文件内容。
- [T08-A14] `npm run verify` 通过。验证：命令输出。
