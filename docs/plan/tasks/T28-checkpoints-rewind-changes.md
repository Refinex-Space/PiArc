## 背景与目标

需求场景 S4 是"改坏了，回到之前"。PiArc 的做法比参考实现更确定：文件工具的每次写入都经过 Core，Core 在写前保存原文件，回退与丢弃改动都基于快照完成，而不是让 agent "请撤销"（`ui-reference-notes.md` 第 6 节）。对话回退复用 Pi 的会话树，原分支保留（ADR-0011）。

本任务实现 piarc-checkpoint、Rewind 四个选项、回退前冲突检测、保留与清理，以及 Changes 面板与会话分支界面。

完成后，用户可以选中任意一条自己的消息回退代码、对话或两者；在 Changes 面板中按文件或按 hunk 丢弃改动；所有路径都有场景或 Playwright 用例覆盖。

## 交付物

### 1. 快照存储

- 每个用户回合开始时建立检查点，键为"会话 + 用户回合 entry id"。
- 回合内经 Core 的每次写入（Write、Edit，及以后的 NotebookEdit）前保存原文件内容到 `checkpoints/objects/`：sha256 寻址、按前缀分桶、相同内容只存一份。新建的文件记为"回退时删除"。
- `checkpoints` 表记录会话、回合 entry id、路径、前后内容 hash、操作类型。对象写入完成后才写索引，避免索引指向不存在的对象。

### 2. Rewind

| 选项 | 代码 | 对话 |
|---|---|---|
| 恢复代码与对话 | 恢复到目标回合开始前 | 在目标用户消息处分支，原分支保留 |
| 只恢复对话 | 不动 | 同上 |
| 只恢复代码 | 恢复到目标回合开始前 | 不动 |
| 从此处摘要 | 不动 | 把目标消息之后的内容压缩为摘要（复用 T27 的摘要提示与 Pi 的分支摘要能力） |

- 入口：transcript 中用户消息的操作菜单"回退到这里"，以及内置命令 `/rewind`。界面列出将被恢复、删除的文件和冲突。
- 冲突检测：恢复前比较每个文件的当前内容与快照记录的最后一次"之后" hash。不一致（被外部或 Bash 修改过）时列出冲突，用户逐个选择"用快照覆盖"或"保留当前"，也可以取消整个回退。
- 执行代码恢复前，先把受影响文件的当前内容存入同一存储；某个文件恢复失败时停止并报告逐文件结果，用户可以用这份快照撤销已完成的部分。
- 只被 Bash 改动的文件不在快照内：回退界面与 Changes 面板明确说明，并建议配合 git 使用。
- 写回经 piarc-fs 的保真写入（换行、编码、BOM），并更新文件状态表，使 agent 下次编辑前必须重新读取。

### 3. 保留与清理

- 每会话保留最近 100 个检查点；会话 30 天未访问后清理其快照；清理后回收无引用的对象。数值可配置，时钟可注入。

### 4. Changes 面板

- 列出本会话改过的文件（基线为该文件在本会话第一次被写之前的内容），每个文件显示统一 diff、增删行数与语法高亮（复用渲染进程 Worker 中的高亮）。
- 大 diff 降级：超过第 7.7 节阈值（例如 5,000 行或 300 个文件）时折叠为纯文本，可手动展开单个文件。
- 按文件丢弃：恢复为基线内容（新建文件则删除）。按 hunk 丢弃：对当前内容反向应用该 hunk；文件在显示 diff 之后又被改动时先刷新，不在旧 diff 上操作。
- 会话右栏改动卡片显示总增删行数，点击打开面板；快捷键 Mod+Shift+D。

### 5. 会话分支

- 用户消息操作菜单"从这里分支"：基于 T14 的 fork，在该消息处创建新分支。
- 分支切换：在有多个分支的位置显示分支切换控件，切换后 transcript、任务清单（T26）随之变化。

### 6. L2 场景与能力 ID

场景放在 `tests/scenarios/rewind-*.yaml`、`changes-*.yaml`，能力 ID 形如 `CAP-REWIND-CODE-001`、`CAP-CHANGES-HUNK-001`。

## 实现要点

- piarc-fs 调用 piarc-checkpoint 是架构允许的单向例外；确认 `crates/deps-rules.json` 中已列出该例外与理由，没有就补上。
- hunk 反向应用要处理相邻 hunk 的偏移变化与 CRLF 文件；用 piarc-diff 的结构，不自己再算一遍 diff。
- 对话回退只移动或新建分支，不删除 JSONL 中的任何 entry（ADR-0011：Core 只读 JSONL）。
- 清理任务在后台运行，不阻塞会话；正在被回退流程引用的对象不能被回收。

## 验收标准

- [T28-A01] 每个用户回合建立检查点，写前保存原文件；内容相同的文件在对象存储中只有一份。验证：测试（对象计数）。
- [T28-A02] 回合内新建的文件在恢复代码时被删除。验证：场景测试。
- [T28-A03] Rewind 四个选项各有场景：文件副作用符合交付物 2 的表，对话分支与摘要内容由 mock provider 请求断言确认。验证：场景测试。
- [T28-A04] 恢复对话后原分支仍在，可以切换回去且内容完整。验证：场景测试与 Playwright 流程。
- [T28-A05] 文件在快照后被外部或 Bash 修改时，回退前列出冲突，用户的逐文件选择被正确执行，取消时没有文件改动。验证：场景测试。
- [T28-A06] 恢复中途某个文件失败时，回退停止并报告逐文件结果，已恢复的部分可以撤销。验证：测试（注入写入失败）。
- [T28-A07] 只被 Bash 改动的文件不出现在快照中，回退界面与 Changes 面板显示相应说明。验证：场景测试与截图（`tmp/evidence/T28/`）。
- [T28-A08] Changes 面板按文件显示统一 diff、增删行数与语法高亮，超过阈值时降级为纯文本。验证：Playwright 流程与截图。
- [T28-A09] 按文件与按 hunk 丢弃后文件内容正确，CRLF、BOM 文件保真，文件状态表要求 agent 重新读取。验证：单测与 Playwright 流程。
- [T28-A10] 每会话超过 100 个检查点时删除最旧的，30 天未访问的会话快照被清理，无引用对象被回收。验证：测试（时钟可注入）。
- [T28-A11] 从某条消息创建分支、在分支之间切换，transcript 与任务清单随之变化。验证：Playwright 流程与截图。
- [T28-A12] `npm run verify` 通过。验证：命令输出。
