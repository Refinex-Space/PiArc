开工前完整阅读 `docs/plan/protocol.md` 并严格遵守。开工检查、范围与决策分级、质量门禁、验收记录、收尾与报告格式都以它为准。最重要的几条：

- 先读后写；外部 API 以锁定版本为准，Pi 的读法见 `docs/plan/references.md`。
- 只做本任务范围内的事；补充型决策自己定，变更型决策写 ADR 提议后停止受影响部分。
- clean-room：参考仓库只学行为，不复制 claude-code 与 OpenClaudeDesktop 生成组件的任何代码、提示词和品牌资产（ADR-0006）。
- 不删改测试和验收项；只有亲自验证通过的验收项才能标 `passing`。
- 每完成一个检查项就更新 `PLAN.md` 检查点并提交；上下文会被自动压缩，不要提前停下。
- 不推送，不打印凭据。

## 背景与目标

M3 交付了 PiArc 并发度最高、对外接触面最大的一批能力：进程内子 agent、后台任务与 Monitor、终端、worktree 与多窗口、MCP 共享连接池、skills 与命令、`http` 与 `prompt` hooks（T31–T38）。W2 在 Windows 上补齐了 M2。风险集中在三处：并发与取消的正确性、MCP 与终端带来的新攻击面、项目级扩展在信任前后的边界。

本任务按 M3 退出标准验收（3 个并行会话 + 子 agent 满足第 11 章内存预算），做四个独立审查并逐条处理发现，确认 W2 的结论，给出"是否进入 M4"的结论与 W3 的重点核对项。

## 范围

### 要做

- 复测 M3 退出标准；确认能力覆盖与验收项状态。
- 四个独立只读审查，逐条核实与处理。
- 确认 W2；检查 ADR-0010 与 ADR-0017 的触发条件；处理登记事项。
- 同步架构文档；写 `docs/reviews/R4-findings.md` 并在开头给出结论与 W3 重点核对项。

### 不做

- 新功能开发。确认的问题在本任务内修复；需要重新设计的登记到具体任务。
- 放宽第 11 章预算：预算只能收紧，放宽须走 ADR 与修订记录，本任务不做。
- Windows 上的 M3 验收（W3）。本任务只给出 W3 需要重点核对的项。

## 交付物

### 1. M3 退出标准复测

- 在当前主线上运行 T35 的测量脚本，场景补上 T35 之后加入的能力：同一工作区 3 个并行会话（至少 1 个在独立 worktree）、1 个子 agent、1 个被各会话共享的 stdio MCP server、已加载的 skills 索引。
- 对照第 11 章当前值：Agent Host 按活动会话数计算的上限（子 agent 计为一个活动会话）、应用其余进程合计上限。数据与 T35 的结果并列，差异超过 10% 时说明原因。
- 不达标时定位原因；本任务内能修的修，修不了的作为阻塞项写进结论。
- 重新生成 `docs/product/capabilities.md`，确认没有 MISSING，且 `check-capabilities.mjs --milestone M3` 不列出 `planned` 能力；T31–T38 与 W2 的验收项为 `passing`，或为 `blocked` 且原因在评审文件中被接受。

### 2. 独立审查

用只读审查子代理（例如 `read-only-reviewer`）并行执行四个审查。每个子代理只拿到审查范围、代码位置与相关架构章节，不拿到你的判断。

| 审查 | 重点 |
|---|---|
| 子 agent 与并发 | 深度与并发计数是否只有一处来源；取消沿会话 → 子 agent → 工具调用 → 子进程的传播；父子互等与死锁；审批来源与"本会话允许"的作用范围；子会话状态隔离；任务管理器的竞态；Agent Host 重启时后台任务与子 agent 的状态；多窗口审批账本 |
| MCP 与终端安全 | 信任闸门；OAuth token 存储与刷新；stdio server 的环境变量与孤儿进程；`requiresUserInteraction`；MCP 输出进入模型时的截断；终端回调（`CLIPBOARD_READ`、`WRITE_PTY`）；粘贴安全检查；链接确认；agent 读屏的共享校验；snapshot 文件中敏感输出的存放与清理；帧协议与输入接口的输入校验 |
| 扩展加载与信任 | skills、命令、子 agent 定义、输出风格、MCP、`http`/`prompt` hooks、frontmatter 中的 hooks 与 `mcpServers` 在信任前后的行为；`allowed-tools` 免审批的边界；`piarc://` 链接参数；worktree 共享信任与规则；配置诊断是否列全来源 |
| 工程质量 | crate 依赖规则；错误类型化；超长文件与函数；定义了却没接线的代码；测试纪律（场景名与断言一致、无静默跳过）；CLAUDE.md 与代码一致；通用能力复用表；平台差异是否收敛在适配层 |

### 3. 发现处理

- 每条发现亲自核实：能复现的先写失败测试再修复；不同意的写理由；属于后续任务的登记到具体任务。
- `docs/reviews/R4-findings.md` 按 `docs/reviews/README.md` 的格式记录每条发现：编号、维度、文件与行号、失败场景、核实结论、处理；附各子代理的范围、输入与原始结论摘要。

### 4. W2 确认与登记事项

- 确认 W2 在看板中为"已完成"，其报告逐条覆盖 M2 退出标准与 R3 列出的重点核对项；W2 列出的、需要用户更新的 T23–T30 验收项在评审文件中汇总。
- 逐条处理 `PLAN.md`"登记事项"：已解决的关闭，仍有效的指定处理任务，不再相关的写明理由后关闭。

### 5. 触发条件、文档与结论

- 逐条检查 ADR-0010（跨会话串扰、单进程崩溃率）与 ADR-0017（自研渲染器在 M3 是否达标、Windows 链接与运行、上游变化）的重新评估触发条件，结果写进评审文件；触发时按决策分级处理。
- 架构文档：第 16 章标注 M3（macOS）状态，第 6.0 节矩阵与实现一致，第 6.15 节数值与代码常量一致；递增版本号并写修订记录。
- 结论写在评审文件开头：M3（macOS）是否达标、进入 M4 的前提条件、W3 需要重点核对的项（ConPTY 终端与 IME、MCP 的 `npx`、worktree 路径、托盘、多窗口、3 会话内存、Windows 基准机性能数据、Narrator/NVDA，以及 T34、T35 登记的 Windows 核对项）。

## 实现要点

- 审查子代理之间互不可见，避免结论趋同；你只在汇总时比对重复项。子代理的结论可能误报，也可能漏报，核实是本任务的主要工作。
- 修复遵守原任务的范围与验收项，不顺手重构；每个修复一个提交，提交说明引用发现编号；修复后跑受影响 crate 或包的测试，收尾时跑一次全量 verify。
- 内存测量在同一台机器、相同负载下进行，记录机型、系统版本、内存与运行时长。

## 验收标准

- [R4-A01] 当前主线上，同一工作区 3 个并行会话加 1 个子 agent（共享 1 个 stdio MCP server、已加载 skills 索引）的稳态内存满足第 11 章预算。验证：测量脚本输出与 `docs/reviews/R4-findings.md` 中的数据。
- [R4-A02] `docs/product/capabilities.md` 重新生成且没有 MISSING，`--milestone M3` 不列出 `planned` 能力。验证：两条命令的输出。
- [R4-A03] T31–T38 与 W2 的验收项全部为 `passing`，或为 `blocked` 且原因在评审文件中被接受。验证：`acceptance.json` 检查输出。
- [R4-A04] 子 agent 与并发、MCP 与终端安全、扩展加载与信任、工程质量四个审查子代理并行运行且相互独立，各自的范围与输入记录在评审文件中。验证：评审文件内容。
- [R4-A05] 每条审查发现都有核实结果与处理方式（修复、不同意并给理由、登记到具体任务），每个修复都附带先失败后通过的回归测试。验证：`docs/reviews/R4-findings.md`、提交记录与测试输出。
- [R4-A06] W2 状态为"已完成"，其报告逐条覆盖 M2 退出标准与 R3 重点核对项；需要用户更新的 T23–T30 验收项已汇总。验证：`PLAN.md`、W2 报告与评审文件。
- [R4-A07] ADR-0010 与 ADR-0017 的重新评估触发条件逐条检查并有结论。验证：评审文件中的检查表。
- [R4-A08] `PLAN.md`"登记事项"中每一条都已关闭或指定了处理任务。验证：`PLAN.md` 内容。
- [R4-A09] 架构文档第 16 章、第 6.0 节、第 6.15 节已按实际更新，版本号递增并有修订记录。验证：文档 diff。
- [R4-A10] 评审文件开头给出明确结论：M3（macOS）是否达标、进入 M4 的前提条件、W3 重点核对项。验证：评审文件内容。
- [R4-A11] `npm run verify` 通过。验证：命令输出。
