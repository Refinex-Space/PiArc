## 背景与目标

第 15.1 节规定 Windows 最迟在下一个里程碑结束前达到同样的退出标准：M3 的 Windows 验收必须在 M4 结束（R5）前完成。两个平台的 CI 一直在跑，代码层面没有坏；本任务在 Windows 11 实机上确认 M3 的功能真的可用，尤其是 CI 测不到的部分：ConPTY 终端与输入法、内置 Node 启动 MCP、Windows 路径下的 worktree、托盘、多窗口、内存与性能数据、Narrator 与 NVDA。

发现的问题当场修复（补充型）或写 ADR（变更型）；修不了的登记，并给出建议归属的任务。

开工时检查 `PLAN.md`：T44、T43 未完成时，先做其余各项，A09、A10 标 `blocked` 并写明原因，任务状态为"部分完成"；两项依赖完成后再续做，仍须在 R5 之前完成。

## 范围

### 要做

- M3 退出标准在 Windows 实机验收：3 个并行会话 + 子 agent 的内存预算。
- 逐项实机核对：ConPTY 终端与输入法、MCP 经 npx 与内置 Node、worktree 路径、托盘、多窗口、`piarc://` 与资源管理器打开文件夹、Windows 基准机性能数据、Narrator 与 NVDA。
- 修复平台问题或登记。

### 不做

- M4 功能在 Windows 上的验收（W4），例如可操作通知的 Toast 实机验证。
- 关闭用户的系统安全设置（Defender、智能应用控制）；需要时只记录现象。

## 交付物

### 1. 环境准备

- 记录机器配置（CPU、内存、磁盘、Windows 11 版本与构建号、x64 或 arm64），与第 11 章的 Windows 基准机型对比。
- 用 CI 产出的 Velopack 安装包安装（不签名，SmartScreen 放行由用户操作），同时保留开发构建用于测试。
- 安装 NVDA 属于全局安装，先征得用户同意。

### 2. 核对清单

| 项 | 核对内容 | 证据 |
|---|---|---|
| 终端（ConPTY） | PowerShell、Git Bash 及其中的交互程序（Git 自带的 vim、less 等）渲染正确；窗口缩放后重排；中文宽字符；Ctrl+C 有选区时复制、无选区时发给终端；snapshot 重启后恢复 | 截图、测试输出 |
| 输入法 | 微软拼音在终端与 composer 中的预编辑文本与候选框位置；合成期间 Enter、Esc 不触发业务；有日文输入法时同样核对 | 截图、操作记录 |
| 终端性能 | 回显额外延迟 p95 ≤ 5 ms；大量输出（`cat` 100 MB 或等价命令）期间主进程事件循环延迟 p99 ≤ 16 ms | 测量输出 |
| MCP | 在没有系统 Node（或从 PATH 中移除）的条件下，npx 类 MCP server 由内置 Node 启动；两个会话共享同一 server 进程；OAuth 经系统浏览器完成（mock 授权服务器） | 进程路径、测试输出 |
| worktree | 含空格与中文的路径、超过 260 字符的路径下创建、使用、归档清理；`.worktreeinclude` 复制；信任与规则按主 checkout 共享（盘符大小写不同也识别为同一仓库） | 场景测试、操作记录 |
| 托盘 | 关闭窗口后托盘常驻；图标计数与运行中、等待审批的会话数一致；从托盘恢复窗口 | 截图 |
| 多窗口 | 两个窗口同时显示同一审批，只接受第一个答复，另一窗口同步更新 | Windows 上的 Playwright |
| URL 与打开文件夹 | `piarc://` 链接唤起应用；从资源管理器右键菜单打开文件夹（方式随安装包形式） | 操作记录 |
| 内存（M3 退出标准） | 3 个并行会话 + 子 agent 场景下，Agent Host、主进程、渲染进程与合计内存对照第 11 章 | 测量输出 |
| 性能 | 用 T44 的脚本测量第 11 章全部可测指标，结果写入 `docs/engineering/performance.md` 的 Windows 一节 | 性能文档 |
| 读屏 | 按 `docs/engineering/accessibility.md` 的核对清单，用 Narrator 与 NVDA 逐项核对并填写结论；高对比度主题（强制颜色）下界面可用 | 清单结论、截图 |

R4 与 `PLAN.md` 登记事项中为 W3 列出的其他核对项逐条并入本清单。需要用户在系统界面上操作的步骤（SmartScreen 放行、读屏软件的实际收听），准备好逐步清单请用户完成，记录用户反馈的结果。

### 3. 问题处理

- 每个问题先写能复现的失败测试（实机才能复现的写清复现步骤），再修复；修复属于平台适配层，业务代码不出现平台分支（第 15.3 节）。
- 修不了或超出本任务范围的问题登记到 `PLAN.md`"登记事项"，写明现象、影响与建议归属（例如 W4 或具体任务）。

### 4. 结论

- `PLAN.md` 会话日志中写 W3 结论：M3 退出标准是否在 Windows 达标、逐项证据位置、未达标项与登记编号。R5 会据此确认。

## 实现要点

- 路径问题优先查规范化：盘符大小写、`\\?\` 前缀、UNC、保留文件名（`CON`、`NUL`）；测试夹具补上 Windows 特有的路径形态。
- 测内存与性能时关闭其他大型程序，记录 Defender 实时保护是否开启；数据偏离基准机型时在文档中说明配置差异，不调整预算。
- Windows 上执行脚本用 Node，不写 PowerShell 专用脚本。

## 验收标准

- [W3-A01] 3 个并行会话 + 子 agent 场景下，各进程内存满足第 11 章预算（M3 退出标准）。验证：测量输出（含机器配置）。
- [W3-A02] ConPTY 下 PowerShell、Git Bash 及其中的交互程序渲染正确，窗口缩放后重排正确，Ctrl+C 有选区时复制、无选区时发给终端，snapshot 在重启后恢复。验证：截图与测试输出。
- [W3-A03] 微软拼音在终端与 composer 中的预编辑文本和候选框位置正确，合成期间 Enter、Esc 不触发业务。验证：截图与操作记录。
- [W3-A04] 终端键入回显额外延迟 p95 ≤ 5 ms，大量输出期间主进程事件循环延迟 p99 ≤ 16 ms。验证：测量输出。
- [W3-A05] 没有系统 Node 时，npx 类 MCP server 由内置 Node 启动，两个会话共享同一 server 进程。验证：进程路径与测试输出。
- [W3-A06] worktree 在含空格与中文的路径、超过 260 字符的路径下创建、使用与清理成功，盘符大小写不同的同一仓库共享信任与规则。验证：场景测试与操作记录。
- [W3-A07] 关闭窗口后应用在托盘常驻，图标计数与运行中、等待审批的会话数一致，可从托盘恢复窗口。验证：截图。
- [W3-A08] 两个窗口同时显示同一审批时只接受第一个答复且另一窗口同步更新；`piarc://` 链接与资源管理器右键菜单打开文件夹可用。验证：Windows 上的 Playwright 输出与操作记录。
- [W3-A09] 第 11 章全部可自动测量的指标已在 Windows 实机测量并写入 `docs/engineering/performance.md`，未达标项已登记。验证：性能文档的 Windows 一节。
- [W3-A10] Narrator 与 NVDA 按读屏核对清单逐项有结论，高对比度主题下界面可用。验证：`docs/engineering/accessibility.md` 的 Windows 结论与截图。
- [W3-A11] 发现的平台问题都有处理：已修复（附复现测试或复现步骤）或已登记（附建议归属）。验证：问题清单与 `PLAN.md` 登记事项。
- [W3-A12] Windows 上 `npm run verify` 通过。验证：命令输出。
