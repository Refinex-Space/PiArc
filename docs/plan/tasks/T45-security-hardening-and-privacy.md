## 背景与目标

M4 退出标准之一是"安全威胁表逐条有测试"（第 16 章），NFR-03 也要求威胁模型逐条有对策与测试。对策分散在 T03 到 T42 的各个任务里，测试也散落各处，没有一张表能证明"每条威胁都被测到了"。本任务建立这张映射表并让它进入 verify，补齐缺口，同时完成四项收尾工作：Electron 安全清单复核、依赖审计、日志与诊断包脱敏、遥测默认关闭的检查。

完成后，架构第 10.1 节的每条威胁都有编号与测试 ID，删掉任何一条映射或引用不存在的测试，verify 都会失败。

### 2. Electron 安全清单复核

- 对照当时锁定 Electron 版本的官方安全文档逐条复核（以锁定版本为准，不沿用 S10 时的版本），写入 `docs/security/electron-checklist.md`：每条的落实方式、测试 ID、与 S10 时的差异。

### 3. 依赖审计

- cargo-audit、npm audit（全部工作区与 agent-host 打包进去的依赖），加上 cargo-deny 已有的许可证检查与 npm 依赖的许可证检查。
- 高危与严重问题全部处理：升级修复，或写入例外清单（理由、影响分析、复查日期）。接入 CI 的依赖安全流水线，本地一条命令可运行。

### 4. 日志、诊断包与遥测

- 日志写入时脱敏：tracing 层把保险箱中已加载凭据的原值、常见密钥格式（服务商 API key 前缀、云厂商 access key、Bearer token、JWT）替换为占位符；Agent Host 的 stderr 进入 Core 日志前同样处理。
- 诊断包（piarc-telemetry 导出）：内容为日志、版本信息、脱敏后的配置与诊断结果；不含保险箱文件、凭据、会话内容。用户主目录路径替换为 `~`。导出前在界面展示文件清单与脱敏摘要，用户确认后才写出。
- 遥测：全新配置下默认关闭。一次完整 mock 会话中，应用（主进程、渲染进程、Chromium 后台、Agent Host）只向 mock provider 与测试配置的 MCP server 发起连接；Pi 的远程模型目录与版本检查、Chromium 的拼写检查词典下载等外连要么关闭，要么列入报告并说明不含会话内容。

### 5. XSS 载荷集扩充

- 新增载荷类别：`javascript:` / `data:` / `vbscript:` 链接、HTML 实体混淆、带事件属性的 SVG 与 `foreignObject`、`<iframe srcdoc>`、内联样式中的 `url()`、OSC 8 终端超链接、含 HTML 的文件名、Unicode 双向控制字符。
- 覆盖的渲染面：transcript、diff 与 Changes（含行内评论）、审批卡、终端链接、设置页（插件与 MCP server 名称、配置诊断中的值）、应用内通知。
- 断言：以文本呈现、没有脚本执行（页面上的哨兵变量不变）、没有导航、CSP 违规报告只出现在预期位置。

## 实现要点

- 映射表引用测试用稳定 ID：L2 场景用能力 ID，其余测试用测试名；新补的测试在名称中带威胁编号，便于反查。
- 发现的安全缺陷先写失败测试再修；修复涉及放松或改变安全基线的，按变更型处理。
- 外连检查经本地代理或连接记录实现，测试中不依赖外网。

## 验收标准

- [T45-A01] `tests/security/threats.yaml` 为第 10.1 节 13 行威胁各分配编号，每条可自动化对策至少映射一个测试 ID，每条威胁至少一个测试；删除一条映射或引用不存在的测试时 verify 失败。验证：临时删除一条映射时的失败输出，撤销后通过。
- [T45-A02] 映射引用的全部测试在 macOS 与 Windows CI 上通过，`docs/security/threat-coverage.md` 由脚本生成且与测试结果一致。验证：CI 输出与生成命令。
- [T45-A03] 仓库文件、WebFetch 内容、MCP 返回内容诱导执行破坏性命令时，命令进入审批且审批卡显示完整命令；关键路径删除在沙箱自动批准与 `bypassPermissions` 模式下仍询问。验证：L2 场景。
- [T45-A04] "全量恶意仓库"夹具在信任前零执行（无 hook、无 MCP 连接、无插件与扩展加载、项目 allow 规则不生效）；信任后新增的可执行项在再次确认前不运行。验证：L2 场景。
- [T45-A05] Electron 安全清单按锁定版本的官方文档逐条复核，每条有落实方式与测试 ID。验证：`docs/security/electron-checklist.md`。
- [T45-A06] cargo-audit、npm audit 与许可证检查没有未处理的高危与严重问题，例外项写明理由与复查日期。验证：命令输出与例外清单。
- [T45-A07] 已知凭据值、常见密钥格式与 Bearer token 写入日志时被替换为占位符；Agent Host 与 Bash 子进程的环境变量中没有凭据。验证：测试（注入已知密钥后扫描日志文件与子进程环境）。
- [T45-A08] 诊断包导出前展示文件清单与脱敏摘要，用户确认后才写出；导出包中没有凭据、保险箱文件与会话内容，主目录路径替换为 `~`。验证：测试（扫描导出包）与 Playwright 截图。
- [T45-A09] 全新配置下遥测关闭；一次完整 mock 会话中，应用只向 mock provider 与测试配置的 MCP server 发起连接，其余外连已关闭或在报告中逐项说明。验证：测试（连接记录断言）与报告。
- [T45-A10] 扩充后的 XSS 载荷集在交付物 5 列出的全部渲染面上以文本呈现，无脚本执行、无导航。验证：安全回归测试输出。
- [T45-A11] preload 的每个命令以畸形参数调用时返回结构化错误且主进程存活；"总是允许"类规则的修改只能经主进程原生确认框完成。验证：测试。
- [T45-A12] 打包产物上 `ELECTRON_RUN_AS_NODE`、`NODE_OPTIONS`、`--inspect` 不生效。验证：打包产物测试。
- [T45-A13] `npm run verify` 通过。验证：命令输出。
