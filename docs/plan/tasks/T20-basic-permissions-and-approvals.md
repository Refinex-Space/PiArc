## 背景与目标

到目前为止，工具调用要么直接执行，要么按 T16 的约定"需要询问即拒绝"。本任务做出 M1 的权限：Core 的 piarc-policy 按"手动"与"自动接受编辑"两种模式裁决，需要询问时经审批账本把结构化审批请求交给客户端，客户端用四类审批卡与热键收集决定，结果回到模型并写入审计。

权限是安全边界，原则是失败即拒绝（ADR-0004）：Core 的任何一步出错、超时或不可达，都按拒绝处理。

完成后，默认模式下每次写文件和执行命令都会询问；用户可以仅本次允许、本会话允许、总是允许或拒绝并附反馈。规则语法完整版与 Bash 复合命令分析由 T23 补齐。

## 交付物

### 1. 裁决（`policy/evaluate`）

| 情况 | 手动（`default`） | 自动接受编辑（`acceptEdits`） |
|---|---|---|
| 只读工具（Read、Glob、Grep） | 允许 | 允许 |
| 工作区内 Write、Edit | 询问 | 允许 |
| 受保护路径写入、工作区外路径（T16 标记为"需要询问"） | 询问 | 询问 |
| 单个简单命令 `mkdir`/`touch`/`mv`/`cp`，参数都在工作区内 | 询问 | 允许 |
| 其他 Bash 与 PowerShell 命令 | 询问 | 询问 |

- "单个简单命令"的判定保守：命令中出现任何 shell 元字符（`;`、`&`、`|`、`<`、`>`、`$`、反引号、括号、换行等）都不算，按询问处理。T23 用语法分析替换这段判定。
- 本会话允许、总是允许产生的规则在模式默认之前生效（裁决第 6 步的 M1 形式）：只做规则文本与本次调用的精确匹配；T23 实现完整语法后替换。
- 未信任工作区中，项目级 allow 规则不生效（第 10.2 节）。
- 每次裁决写入 `audit_events`：工具、参数摘要、模式、命中的规则或步骤、结论、来源（自动或用户）。

### 2. 审批账本

- 每个审批请求有 `requestId`、所属会话、`revision`、`connectionEpoch`；Core 的审批账本是唯一事实来源，以实体快照推给所有窗口。
- 多个窗口同时显示时只接受第一个有效答复，其余答复返回"已处理"；`revision` 不匹配的答复被拒绝。
- Agent Host 重连（`connectionEpoch` 变化）后，旧请求全部作废，按拒绝回给模型。
- `policy/evaluate` 等待用户时不设固定超时，会话中断时取消；Core 内部任一步失败、Agent Host 侧调用超时或解析失败，一律按拒绝处理。

### 3. 审批选项

- 仅本次允许、本会话允许（会话内存中的规则）、总是允许、拒绝（可附反馈，反馈作为拒绝理由回给模型，对应 item 状态为 `declined`）。
- 总是允许：生成精确规则（如 `Bash(npm test)`、`Edit(src/a.ts)`；越界目录写入 `permissions.additionalDirectories`），在卡片中可编辑，再由主进程弹出原生确认框，确认后写入 `.piarc/settings.local.json`（第 10.3 节）。
- 受保护路径写入不提供"总是允许"（官方行为：allow 规则不能预批准受保护路径）。

### 4. 模式

- 起始模式：会话显式指定 → 设置中的 `permissions.defaultMode` → `default`；项目级配置中的 `bypassPermissions` 与 `auto` 不生效。M1 的模式菜单只提供"手动"与"自动接受编辑"。
- 切换模式是一条会话事件，写入会话 entry，transcript 中显示，会话恢复后模式随之恢复。
- 环境栏模式菜单：Mod+Shift+M 打开，数字键快选（注册到 T18 的快捷键注册表）。

### 5. 审批卡

- 四类：命令（完整命令文本、cwd）、文件改动（结构化 diff 预览）、权限扩展（越界目录）、提问表单。提问表单在本任务只定义类型与路由：收到时显示"当前版本不支持"并按拒绝回复，控件由 T26 实现。
- 审批卡作为 transcript 行出现（T19 的行组件注册方式）。
- 热键：Mod+Enter 允许、Mod+Shift+Enter 本会话允许、Esc 拒绝（仅当 composer 为空或焦点在卡片上）；新卡出现后 400 ms 内不响应热键；多张卡时只有第一张可见卡响应；输入法合成期间不响应。
- 长参数阅读闸门：被折叠的长命令或长 diff 未展开查看时，"总是允许"按钮不可用。
- 会话状态"等待审批"由账本驱动，侧栏徽标与通知随之更新（T18）。

## 实现要点

- 裁决函数是纯函数：输入工具调用、模式、规则、信任状态、路径判断结果，输出结论与理由；I/O 在外层。这样模式矩阵可以穷举测试。
- 热键判定、防误触计时、阅读闸门、输入法守卫写成纯函数做 L0 单测，再用 Playwright 覆盖真实按键。
- Playwright 无法点击原生对话框：测试中通过 `electronApp.evaluate` 替换主进程的对话框函数，并断言它被调用、参数中带规则文本。
- 拒绝理由与反馈是给模型看的：写清楚谁拒绝了、为什么、模型下一步可以怎么做。

## 验收标准

- [T20-A01] 交付物 1 表中的每个单元格都有对应场景，两种模式下的结论与表一致。验证：L2 场景输出。
- [T20-A02] 含 shell 元字符的 `mkdir`/`cp` 命令在自动接受编辑模式下询问；参数指向工作区外时询问。验证：单测与场景测试。
- [T20-A03] Core 返回错误、`policy/evaluate` 超时、响应无法解析时，工具调用都被拒绝且模型收到拒绝理由。验证：故障注入测试。
- [T20-A04] 两个窗口同时答复同一请求时只有第一个生效，第二个收到"已处理"；`revision` 不匹配的答复被拒绝。验证：测试。
- [T20-A05] Agent Host 重连后，重连前未答复的审批请求全部作废并按拒绝回给模型，界面上的旧卡片消失。验证：测试。
- [T20-A06] 本会话允许只在本会话内对同一调用免审批，新会话中仍询问；拒绝附带的反馈出现在下一次模型请求的工具结果中，item 状态为 `declined`。验证：场景测试与 mock provider 请求断言。
- [T20-A07] 总是允许的规则可在卡片中编辑，经主进程原生确认后写入 `.piarc/settings.local.json`；之后同一调用不再询问；受保护路径的卡片上没有"总是允许"。验证：Playwright 流程、文件内容与场景测试。
- [T20-A08] 起始模式按"会话 → 设置 → default"解析；项目级配置把 `defaultMode` 设为 `bypassPermissions` 或 `auto` 时不生效。验证：测试。
- [T20-A09] 切换模式后 transcript 中出现模式切换行，重启应用并恢复会话后模式保持。验证：场景测试与 Playwright 流程。
- [T20-A10] 每次裁决都写入审计表，可按会话查询到工具、模式、命中步骤与结论。验证：测试。
- [T20-A11] 四类审批卡按类型渲染，提问表单类型显示不支持提示并按拒绝回复。验证：组件测试与截图（`tmp/evidence/T20/`）。
- [T20-A12] 新卡 400 ms 内热键无效；多张卡时只有第一张响应；composer 非空且焦点不在卡片上时 Esc 不拒绝；输入法合成期间热键无效；长参数未展开时"总是允许"不可用。验证：单测与 Playwright 流程。
- [T20-A13] 无需用户参与的裁决 p95 ≤ 2 ms。验证：Core 基准测试输出。
