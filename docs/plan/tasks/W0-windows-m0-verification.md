# W0 Windows：M0 验证项实机确认

| 项 | 内容 |
|---|---|
| 阶段 | 1 M0 技术验证 |
| 依赖 | T08–T12 |
| 执行平台 | Windows 11（x64；有 arm64 设备时同时覆盖） |
| 推荐配置 | Opus 5.5，effort high，新会话 |
| 规模 | 中 |
| 关联验证项 | S1、S2、S5、S6、S7、S8 的 Windows 部分 |
| 需要的用户决定 | 无 |

启动方式：先在 macOS 上推送；在 Windows 11 电脑上 `git pull` 同步后，于仓库根目录开新会话，输入 `/task W0`，或粘贴本文件全部内容。

## 执行要求

开工前完整阅读 `docs/plan/protocol.md` 并严格遵守。开工检查、范围与决策分级、质量门禁、验收记录、收尾与报告格式都以它为准。最重要的几条：

- 先读后写；外部 API 以锁定版本为准，Pi 的读法见 `docs/plan/references.md`。
- 只做本任务范围内的事；补充型决策自己定，变更型决策写 ADR 提议后停止受影响部分。
- clean-room：参考仓库只学行为，不复制 claude-code 与 OpenClaudeDesktop 生成组件的任何代码、提示词和品牌资产（ADR-0006）。
- 不删改测试和验收项；只有亲自验证通过的验收项才能标 `passing`。
- 每完成一个检查项就更新 `PLAN.md` 检查点并提交；上下文会被自动压缩，不要提前停下。
- 不推送，不打印凭据。

## 背景与目标

M0 的退出标准要求每个验证项在 macOS 与 Windows 上分别给结论（架构第 16 章）。CI 证明了代码能在 Windows 上构建并通过测试，但输入法、真实性能、凭据管理器、SmartScreen、ConPTY、arm64 实机这些只能在真机上确认。

本任务在 Windows 11 实机上补齐 S1、S2、S5、S6、S7、S8 的 Windows 结论，写回各自的报告；同时关闭 M0 任务中因"需要 Windows"而标为 `blocked` 的验收项（协议"验收记录"中的 W 系列例外）。S3、S4、S9、S10 的 Windows 结论来自 CI，本任务只在关闭对应 `blocked` 项时核对 CI 结果或在本机复跑。

发现平台问题时：补充型直接修复（先写能复现的失败测试），变更型写 ADR 提议并停止受影响部分。

## 范围

### 要做

- 准备 Windows 开发环境，跑通开工基线。
- S1、S2、S5、S6、S7、S8 的 Windows 实机验证。
- 关闭 M0 任务中因"需要 Windows"而 `blocked` 的验收项。
- 修复或登记发现的平台问题；把 Windows 结论写回各报告与 `docs/spikes/README.md`。

### 不做

- M1 功能在 Windows 上的验收（W1）；Windows 隔离方案评估（T39）。
- 更新流程与界面（T50）：本任务只验证 Velopack 更新机制是否可行。
- 修改用户的系统安全设置（SmartScreen、智能应用控制、Defender），也不建议用户修改。

## 交付物

### 0. 环境

- 记录机器信息：CPU、内存、磁盘、Windows 版本与构建号、架构，与第 11 章 Windows 基准机型（x64 8 核 / 16 GB / NVMe SSD）对照。
- 开发环境缺组件（Rust MSVC 工具链、Node、Git for Windows 等）时，列出缺什么、为什么需要，征得用户同意后再安装。
- 开工基线按协议执行：环境缺失补齐后重跑；`npm run verify` 因代码问题失败时，说明 Windows CI 没有覆盖到，按协议停止并报告。

### 1. S1 transcript 与 composer

- 运行 T09 的自动化测试与性能测量（100 token/s 流式、1 万条滚动、1,000 条冷加载、渲染进程内存），与第 11 章预算和 macOS 数据对照。
- 真实输入法核对（实机关口）：微软拼音在 composer 中合成期间，Enter、Esc、`/`、`@` 不触发业务。日文输入法需要安装语言包，属于系统配置变更，征得同意后再做；不同意则记录"未验证"。

### 2. S2 NAPI 事件通道

- win32-x64：开发模式与打包产物都能加载 `.node`；运行 T04 的完整基准（10 万事件/分钟持续 5 分钟、事件循环延迟、同步调用）。
- win32-arm64：有 arm64 设备时加载并运行基准；没有时记录"未验证"，列为 R1 的跟进项。

### 3. S5 凭据保险箱

- 凭据管理器中主密钥的创建、读取、删除与错误路径（测试服务名，结束后清理）；T08 的保险箱测试与无明文扫描在 Windows 数据目录上通过。

### 4. S6 安装与首次运行

- 安装包由用户从 CI 产物经浏览器下载（带"来自网络"标记）：
  - SmartScreen（实机关口）：用户按"更多信息 → 仍要运行"放行，记录每一步的界面与结果；
  - 安装：按用户安装、不弹 UAC；启动后 Core 经 Job Object 启动内置 node 运行 Agent Host，完成一轮 mock 对话；
  - 卸载后检查安装目录、开始菜单与数据目录的残留；
  - 用 T12 产出的相邻两个版本验证 Velopack 更新机制是否可行；
  - 记录安装包与安装后体积（对照第 11 章）以及 Defender 是否报警。
- 智能应用控制（实机关口）：请用户在"Windows 安全中心"中查看并告知当前状态，只记录当前状态下的表现。状态为关闭时，结论写"未实测，按 ADR-0018 预期为无法运行"。

### 5. S7 终端

- 在打包产物中验证 T10 选定的 MSVC 链接方式；ConPTY 下启动 shell、调整尺寸、Ctrl+C、终止进程；对比是否随附 `conpty.dll` 与 OpenConsole.exe 的差异，给出建议。
- TUI 渲染截图（vim 等本机可用的程序）；formatter 与帧逐格一致的测试在 Windows 上通过。
- 键入回显额外延迟 p95；输出 100 MB 时主进程事件循环延迟 p99。
- 微软拼音在终端中的候选框与预编辑位置（实机关口，截图）。
- win32-arm64：有设备时链接并运行；没有时记录"未验证"（ADR-0017 的触发条件依赖它），列为 R1 的跟进项。

### 6. S8 Job Object

- 实机验证 Job Object 终止多级进程树（例如 PowerShell → cmd → node），用进程列表确认无残留。
- 在任务管理器中结束主进程后，Agent Host 及其子进程全部退出。

### 7. 收口

- 平台问题：补充型先写失败测试再修复；变更型写 ADR 提议，停止受影响部分；不属于本任务的写进 `PLAN.md`"登记事项"。
- 逐项处理 T02–T12 中因"需要 Windows"而 `blocked` 的验收项：在 Windows 上验证通过后改为 `passing`，`evidence` 以"由 W0 在 Windows 上验证："开头；对应任务在看板中从"部分完成"改为"已完成"。
- 每份报告的 Windows 部分写入环境、步骤、数据、结论（通过 / 有条件通过 / 不通过 / 未验证）；更新 `docs/spikes/README.md` 的 Windows 列。

## 实现要点

- 智能体不能代替用户点击系统界面。到达实机关口时，先完成不需要用户的部分，再把需要用户做的步骤写成清单（做什么、看到什么算通过、要把什么告诉你），状态改为"阻塞（等待用户实机操作）"。
- Windows 专用的检查尽量写成 CI 能运行的测试，避免只在本机跑一次。
- 测量结果超出第 11 章预算时分析原因（Defender 实时扫描、电源模式、机器规格），写进报告，不改预算；预算校准由 R1 负责。

## 验收标准

- [W0-A01] 机器信息（CPU、内存、Windows 版本与构建号、架构）已记录在各报告的 Windows 部分，并与第 11 章基准机型对照。验证：报告内容。
- [W0-A02] S1：T09 的自动化测试在 Windows 上通过；流式、滚动、冷加载、内存的测量数据已记录并与第 11 章预算对照。验证：测试与测量输出。
- [W0-A03] S1：微软拼音合成期间 Enter、Esc、`/`、`@` 不触发业务；日文输入法已验证，或注明"未验证"及原因。验证：用户核对记录与截图（实机关口）。
- [W0-A04] S2：win32-x64 在开发模式与打包产物中加载 `.node`；完整基准无丢失无乱序，主进程事件循环延迟 p99 ≤ 16 ms，同步调用 p99 ≤ 1 ms。验证：基准输出。
- [W0-A05] S5：凭据管理器中主密钥的创建、读取、删除与错误路径通过，测试条目已清理；Windows 数据目录的无明文扫描通过。验证：测试输出。
- [W0-A06] S6：Velopack 安装包按用户安装、不弹 UAC，启动后经 Job Object 运行 Agent Host 并完成一轮 mock 对话，卸载后无残留；体积与 Defender 表现已记录。验证：测试输出、截图与报告。
- [W0-A07] S6：SmartScreen 放行流程的每一步与结果已记录；智能应用控制的当前状态与表现已记录，用户的安全设置未被更改。验证：用户操作记录（实机关口）。
- [W0-A08] S6：相邻两个版本之间的 Velopack 更新机制可行性有结论。验证：操作记录与报告。
- [W0-A09] S7：选定的 MSVC 链接方式在打包产物中可用；ConPTY 下启动、调整尺寸、Ctrl+C、终止进程正常；TUI 截图正确；formatter 与帧逐格一致的测试通过。验证：测试输出与截图。

- [W0-A11] win32-arm64：`.node` 与 libghostty-vt 在 arm64 实机上加载运行，或注明"未验证"并列为 R1 跟进项。验证：测试输出或报告。
- [W0-A12] S8：Job Object 终止多级进程树后无残留；结束主进程后 Agent Host 及其子进程全部退出。验证：测试输出与进程列表。
- [W0-A13] T02–T12 中因"需要 Windows"而 `blocked` 的验收项都已在 Windows 上验证并按协议关闭，或写明仍无法关闭的原因。验证：`acceptance.json` 中的 `evidence` 与看板状态。
