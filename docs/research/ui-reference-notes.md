# UI 与交互参考要点

> 2026-11-14 调研快照。来源：`reference/OpenClaudeDesktop`（Claude Desktop Code 界面复刻，主要分析 `new-2.42304.0`，参考 `next-4.16336.0`）与 `reference/open-claude-ui`（逆向还原的 Claude 设计系统）。只记录信息结构、状态机与交互阈值，不收录代码、图标、字体、配色等资产（ADR-0006）。参考实现的部分细节与其文档不符，下列数值作为 PiArc 的初始参考，在 M0 原型中校准。

## 1. 信息架构

- 三栏：左侧栏按项目分组列出会话；中间是对话与输入框；右侧会话栏由卡片组成（运行环境、上下文、产出、改动）。
- 终端、预览、改动、侧边对话都是可停靠的面板，没有固定底栏。
- 从旧版到新版最大的变化：环境、改动、上下文信息从输入框周围移到右栏；最新版把 Chat、Code、Cowork 合进同一个窗口外壳，并加强多 agent 并行监看（后台任务面板、侧栏悬停直接审批、审批排队）。

## 2. 对话区

- 所有行都从内核的条目流推导：用户消息、回复、思考块（三档视图）、工具组摘要、working 行、bash 卡、改动卡。
- working 行显示：当前工具、计时、token 数、等待审批、正在停止、重试次数、正在压缩。
- 流式输出有节奏控制（平滑输出字符，不落后实际进度太多）。
- 滚动跟随：向上滚动超过约 2 px 即解除跟随，回到底部约 1 px 内重新跟随（复刻实现）；设计系统文档给出的另一组取值是用户滚动后 150 ms 内不抢视口、距底 40 px 内恢复、离底 120 px 显示"回到底部"按钮。
- 生成过程中思考块强制展开，不能折叠。
- 回合结束显示任务清单与"下一步"建议框。

## 3. 审批

- 主进程维护审批账本，按 epoch 与 revision 管理，防止重复回答或回答过期请求。
- 新卡出现后约 400 ms 内不响应快捷键；输入框为空时 Esc 与 ⌘↩ 作用于审批卡；输入法合成期间所有按键忽略。
- 模型给出的长参数需要滚动读完，"允许"按钮才可用。
- 权限模式翻译为"审批策略 + 沙箱策略"的组合。

## 4. 宿主注入的工具

任务清单和"下一步"框不是内核原生能力：宿主启动一个 MCP server，把 `update_plan`、`wrap_up` 这类工具注入给所有内核，UI 再根据调用参数渲染。这让不同内核得到一致的 UI。PiArc 用 Harness Kit 注册的宿主工具实现同样的效果（架构文档 6.5）。

## 5. UI ⇄ 内核协议

- 复刻实现采用 Codex app-server v2 风格的 JSONL 协议，三层结构为 thread → turn → item，生命周期事件 4 种（started / delta / completed，加上回合级事件），增量按 itemId 关联。
- item 状态枚举：inProgress / completed / failed / declined / interrupted；UI 只认语义状态，不自行根据退出码判断成败。
- 内核以能力声明（capabilities）告知支持的功能，UI 按能力显示或隐藏，而不是按内核名字分支。
- ACP、OpenCode、ZCode 三个桥用同一套适配模式映射到这套契约。
- PiArc 借鉴其语义设计 AHP 与 Core → 客户端的事件模型（ADR-0009、架构文档 7.4、7.6）。

## 6. 交互对标优先级（摘要）

- **P0**：窗口骨架与会话右栏；侧栏会话列表（状态优先级：错误 > 等待审批 > 运行中 > 未读 > 空闲）；新建会话流程（乐观气泡、失败回滚）；输入框（多行、输入法安全、@ 提及、/ 命令、附件、运行中 steer 与排队、Esc 停止）；环境栏（权限模式、模型与 effort、上下文用量环）；对话区行模型；working 行；流式渲染与滚动跟随；审批卡；权限模式语义；停止 / 排队 / steer；基础改动面板；模型与服务商设置；错误模型。
- **P1**：任务清单与下一步框；plan 模式完整流程；子 agent 卡；后台任务面板；上下文明细；终端；回退与分支；MCP / skills / 插件 / hooks 设置；侧边对话；面板停靠；MCP elicitation；用量与成本。
- **P2**：动态工作流、定时任务、预览、多会话分屏、侧栏悬停审批、审批队列、Cowork 类表面、computer use、远程控制。
- **建议做得比参考更好**：改动面板支持按 hunk / 文件真正丢弃（参考实现的撤销是给 agent 发消息）；基于快照的确定性回退；审批持久规则的可视化管理；多窗口审批一致性。

## 7. 设计系统的可迁移经验

- **令牌分层**：原始色板 → 明暗阶梯 → 语义层 → 组件层；组件只读语义层。PiArc 采用同样的结构，但色值与品牌完全自定义。
- **交互阈值**：拖拽 4 px 死区；输入法合成期间 Enter 与 Esc 不触发业务；自动重试有次数上限，之后转为手动重试加倒计时；减少动效同时响应系统设置与应用内开关。
- **悬停意图**：约 600 ms 打开、200 ms 关闭的悬停卡片状态机。
- **上下文胶囊**：存储数据、输入框中的胶囊、发送时拼接的内容三者分离，用户界面上看不到拼接进去的结构化文本。

## 8. 原生翻译要点

> 本节写于原生客户端方案期间。客户端改为 Electron + React 后（ADR-0013），参考实现的 Web 做法可以直接对照，本节只有弹簧参数换算和"正文用不透明背景"两条仍然适用；Web 端的对应规则见架构文档第 8.4–8.6 节。

- 弹簧参数换算（Apple SDK 定义）：`response = 2π·√(m/k)`，`dampingFraction = c / (2·√(mk))`；过阻尼参数需要使用允许过阻尼的弹簧构造方式，否则会被当作临界阻尼处理（需单测确认）。
- 滚动跟随：`NSScrollView` + TextKit 2，用滚轮事件与 live scroll 通知判断"用户正在滚动"，内容增长时无动画贴底。
- 输入法守卫：在 `textView(_:doCommandBy:)` 中处理换行，先检查 `hasMarkedText()`；Escape 与 `/`、`@` 触发符同样先检查。
- 材质：侧栏、工具栏、菜单交给系统控件（macOS 26 自动获得 Liquid Glass）；正文、代码块、diff 使用不透明背景。
- 用平台惯例替换 Web 做法：原生标题栏 + `NSToolbar`；`NSMenu` 右键菜单；`Settings` 场景；`NSSplitViewController` 分栏；source list 侧栏。

## 9. 品牌边界（PiArc 必须避免）

- 陶土/橙色系主色；
- "暖奶油底色 + 衬线大标题"的组合；
- 火花类标记符号；
- Anthropic 的专有字体、提示音、图标与插画。
