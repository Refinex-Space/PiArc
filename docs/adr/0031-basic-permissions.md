# 0031. M1 权限预检、审批账本与项目信任（补充）

- 状态：已接受，补充 ADR-0004、ADR-0025、ADR-0026、ADR-0029
- 日期：2026-11-19
- 相关：架构第 6.1.2、6.2、7.4、7.6、8.5、10.2、10.3 节

## 决策

1. Pi 的 `tool_call` 把工具规范名、调用 ID 与输入交给 Core。Core 以会话的工作目录和真实路径判断边界，以 `piarc-policy` 计算模式与精确规则。用户操作期间可以无限期等待：Core 建立账本条目后发 `policy/pending`，Agent Host 此时才撤掉等待 Core 响应的计时器。错误、超时、过期请求均拒绝。超出单帧的输入经 `policy/inputChunk` 按 UTF-8 偏移暂存，接收方核对同一会话、连接、工具与调用。Write 正文仍受原有 64 MiB 上限约束。
2. 账本按会话管理请求和一次性答复通道。会话快照携带模式、请求列表和数量。渲染进程可以请求持久化，主进程原生对话框必须展示并确认最终提交的全部规则或目录。Core 检查请求身份、revision、连接代次和允许的持久化字段。会话规则仅存于内存。
3. 文件和命令的实际委托 I/O 绑定到预检的会话、连接、调用、工具和目标。已有的先读后改、内容新鲜度与原子替换继续由文件层强制执行。自动接受编辑只放行已核实的系统工具或 Git Bash 文件工具。用户自定义启动脚本或工作区可控制命令解析时转为询问。M1 只识别保守的字面命令及精确规则，T23 接管命令语法和规则匹配。
4. 用户确认将项目级自动接受编辑和额外目录纳入信任快照。未确认的项目授权不进入裁决，用户设置及会话显式模式照常生效。原生确认后，仅把本次确认的条目补入已有信任快照，其他新增可执行项仍需确认。
5. 模式切换写入 Pi 会话自定义 entry，历史窗口和实时事件使用同一种模式变更行。连接中断时 Core 可按工具调用 ID 告知恢复后的 Agent Host 哪些审批已经失效，使下一次模型请求得到具体拒绝理由。其他工具沿用 ADR-0026 的中断恢复。

## 依据

Pi 1.5.2 的扩展运行器在工具执行前调用 `tool_call`，接受带理由的阻断结果。复用 Pi 对工具结果和会话 entry 的持久化，避免在 Core 建立第二份 transcript。审批答复和原生确认发生在不同进程，判重、失效与文件边界必须在 Core 收口。项目普通配置可随版本控制变动，未经确认的设置不能扩大已有授权。
