# 0105. 主区是导航表面上的一张卡片，分隔线改为中性细线

- 状态：已接受（用户在 2026-11-27 确认，参照 ChatGPT 桌面端的弱边框）
- 日期：2026-11-27
- 修订：ADR-0073 的视觉基准在窗口区域划分这一项改按本 ADR；架构第 8.6 节"平台外观"
- 相关：ADR-0029（设计令牌）、ADR-0101（设置是工作台里的视图）；[视觉规范](../engineering/visual-design.md)第 1 节

## 背景

用户对照 ChatGPT 桌面端指出两处差距。一是分隔线：侧栏与主区、标题栏下沿、主区与工具面板之间的线取 `border.subtle`，即 slate 阶梯第 6 级（浅色 `#d5d9df`），在白底上是偏蓝的实线；ChatGPT 同样位置是约 4%–8% 的中性黑（截图实测 235–249）。二是整体：ChatGPT 的主区是一张白卡，靠侧栏的两角有约 8–10 px 的圆角，左侧一条极淡的线，顶、右、底贴窗口边；侧栏的底色从卡片圆角外露出来，窗口读作"一块表面上放着一张卡片"。

视觉规范第 1 节本来就要求"区域边界靠背景色差，分隔线用 `session.line`"，现状的 `border.subtle` 没有做到。

## 决策

1. **分隔线**：`border.subtle` 与 `session.line` 同值，浅色 8% 黑、深色 10% 白、高对比度 `neutral.11`。所有读 `border.subtle` 的线随之变为中性细线。侧栏底部（身份与设置按钮之上）不画分隔线。
2. **表面归窗口**：侧栏底色（macOS、Windows 上是盖在系统材质上的 90% 薄纱）由 `.shell` 承担；栅格里的侧栏（工作台的与设置视图的）透明。卡片圆角让出的位置因此与侧栏是同一块表面，不会出现两层薄纱叠加的色差。窄窗下浮在主区上方的侧栏不透明。
3. **主区卡片**：有侧栏在旁时，`.workspace-area`（含标题栏、对话区与工具分块）与设置视图的 `.settings-view` 在靠侧栏的两角取 `radius-lg` 圆角，外加 1 px 的 `session.line` 环，内容按圆角裁切；顶、右、底贴窗口边。侧栏收起或窄窗浮层时，主区就是整个窗口，不做卡片。强制颜色下用 `CanvasText` 的左边线代替阴影环。
4. **侧栏分隔条**只在悬停、拖动与键盘焦点时显示，常态的边由卡片的环画出。

## 备选方案

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| 只换分隔线颜色 | 改动最小 | 区域仍是三块拼接，一体感主要来自卡片 | 作为第 1 步已做，不止于此 |
| 卡片四周内缩，露出一圈侧栏底色 | 卡片感更强 | 四边都损失空间，窗口边缘出现双边；与参照实测不符 | 不采用 |
| 卡片四角都圆、贴边 | 实现最简单 | 右侧两角被窗口圆角或屏幕边截断，看起来是缺口 | 不采用 |
| 继续按 Claude Desktop 的三块拼接 | 符合 ADR-0073 | 用户明确要求向 ChatGPT 的一体感靠拢 | 不采用 |

## 后果

- 正面：窗口读作一块表面加一张卡片；分隔线不再偏蓝，与视觉规范一致。
- 负面与代价：主区内容按圆角裁切（`overflow: clip`），以后若有需要伸出主区的元素，要用 `position: fixed` 或放到 `TooltipLayer` 一类的顶层；会话页与设置页的评审截图需要重拍。
- 需要配套做的事：视觉规范第 1 节写明卡片与表面；架构第 8.6 节同步。

## 重新评估的触发条件

出现以下任一情况时复核本决策：

- ADR-0073 的参照版本更换，且新版本的窗口区域划分与本 ADR 冲突。
- 平台材质的实现变化（例如改用 Liquid Glass），侧栏与卡片外的表面不再能共用一层薄纱。
- 出现必须越过主区边界显示、又不能改为顶层渲染的界面元素。
