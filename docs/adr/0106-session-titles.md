# 0106. 按首条消息自动生成会话标题

- 状态：已接受（补充；用户在 2026-11-27 要求按首条消息生成标题，不再直接显示原文）
- 日期：2026-11-27
- 补充：ADR-0029（会话标题、置顶、归档由 Core 管）、ADR-0086（辅助模型通道上的单次生成请求）
- 相关：架构第 8.2 节（侧栏与会话标题）、第 9.2 节（会话索引）

## 背景

会话列表与标题栏显示的标题依次取用户改的名、Pi 的会话名、首条用户消息（最多 200 个字符）。首条消息很长时，侧栏与标题栏显示的就是一大段原文。

参照实现（只研读行为）：Claude Code 在首条真实文字消息提交后，用小模型生成 3–7 个词的标题，失败时下一条消息再试，恢复的会话不重新生成，用户的改名始终优先；OpenClaude Desktop 先以截断的首条消息占位，再经一次隐藏的单轮请求生成一行标题（与用户语言一致、不加引号与结尾标点、不回答原问题），只在标题仍是占位且未被改名时替换。两者都不阻塞首个回合，没有用户开关。

## 决策

1. **何时生成**：只为本 Core 新建的会话（`create`，含草稿会话；恢复与分叉的不算），在 Core 接受的第一条文字输入之后。以 `/` 开头的命令等下一条；单行且不超过 32 列（中日韩字符算两列）的消息本身就是标题，不发请求；用户已改名的不发请求。每个会话至多请求两次：失败或得到空标题时，下一条被接受的输入再试一次。
2. **怎么生成**：Core 经 AHP `session/title`（能力 `sessionTitle`）请 Agent Host 在该会话的辅助模型通道上发一次请求，与首个回合并行，不进主会话历史。请求只带首条消息（最多 4,000 个 UTF-16 单元，作为不可执行的材料包在 `<message>` 里），要求一行、2–6 个词或 4–12 个中日韩字符、与消息同语言、不加引号与 Markdown 与结尾标点、不回答问题；提示词在 `agent-host/src/harness/prompts/session-title.ts`，纳入原创性检查。答复经 Agent Host 的 `tidyTitle` 与 Core 的 `clean` 清成一行、不超过 80 个字符；用量记为辅助调用，用途 `sessionTitle`（用量页"会话标题"）。
3. **存在哪里**：Core 自有的 `sessions.auto_title`（迁移 17），与 `custom_title` 一样经 `SessionPrefsChange` 写入（行还不存在时先留在会话 actor 里，索引同步后写），重建索引时保留，不写 Pi 的 JSONL。客户端的改名、置顶、归档命令设置不了它。
4. **显示优先级**：用户改的名 › Pi 的会话名 › 自动标题 › 首条消息。生成之前与失败时显示首条消息；标题到达时会话 actor 立即发布快照，侧栏与标题栏无需刷新即更新，标题文字以淡入加轻微失焦的方式就地换上（减少动效时关闭）。
5. **测试**：`SessionsConfig.session_titles` 由应用打开（NAPI `create`），测试默认关闭：标题请求带着首条消息里的场景标记，会占用严格 mock 脚本的一步。`createForTests` 在 `PIARC_TEST_SESSION_TITLES=1` 时打开。

## 备选方案

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| 写成 Pi 的会话名（`setSessionName`，进 JSONL） | 分叉的会话随文件带走标题 | 回合进行中由 Agent Host 往会话文件追加条目；ADR-0029 规定标题由 Core 管 | 不采用 |
| 首个回合结束后再生成 | 请求顺序确定 | 有工具调用的长回合要等几分钟才有标题 | 不采用 |
| 只截断首条消息（首句、去空白、限长） | 不发请求 | 仍是原文，不概括任务 | 作为占位保留（侧栏与标题栏单行省略），不作为方案 |
| 加用户开关 | 可以关掉这次请求 | 参照实现都没有；请求很小，走用户自己选的辅助模型 | 暂不加 |

## 后果

- 正面：长消息开头的会话在首个回合期间就有简短、同语言的标题；改名与旧会话不受影响。
- 负面与代价：每个新会话多一次很小的模型请求（辅助模型没配置时用会话模型）；用户把辅助模型设成另一家服务商时，首条消息会发给那一家。
- 需要配套做的事：L2、会话层与 L4 测试默认关闭标题；需要标题的测试显式打开，并让脚本的两步对标题请求与回合请求给出同一段文字（两者到达 mock 的先后不定）。

## 重新评估的触发条件

出现以下任一情况时复核本决策：

- 用户要求关闭标题生成，或要求在后续消息后重新生成标题。
- Pi 提供会话级的标题字段，或 Core 需要跨分叉保留标题。
- 辅助模型通道的请求方式变化（例如结构化输出成为所有服务商都支持的能力）。
