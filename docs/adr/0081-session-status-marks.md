# 0081. 会话状态徽标对齐参考，仍按形状区分

- 状态：已接受（用户在会话中要求对齐参考）
- 日期：2026-11-25
- 来源：用户反馈"等待处理时，标题左侧和侧栏会话左侧的黄色方框加问号设计不行，对齐参考的等待处理设计"
- 相关：ADR-0029、0073、0078；架构第 8.2 节；`docs/engineering/accessibility.md`

## 背景

T18 定下侧栏与会话标题旁的状态徽标：出错为红色圆形加叹号、等待为黄色方形加问号、运行中为旋转的环（后来换成 PiArc 的活动标记）、未读为圆点。形状各不相同，是为了在强制颜色与色觉障碍下不只靠颜色区分（WCAG 1.4.1）。

参考版本 `next-4.16336.0` 的侧栏状态（`sidebar-status-glyph`）更安静：等待输入是 6 px 的琥珀色实心圆点（`status-dot[data-kind=awaiting]`，不闪动），未读是强调色圆点，出错是危险色的警告图标，提示文字为 "Awaiting input"、"Awaiting answer"。它的等待与未读只靠颜色区分。

## 决策

1. 徽标改用参考的安静小标记：出错是 Lucide 的警告三角（`WarningGlyph`，错误色），等待是琥珀色的圆点，运行中仍是 PiArc 的活动标记，未读仍是强调色圆点。
2. 为保留"形状区分"，等待的圆点外加一圈 1.5 px 的同色细环（靶心形），与未读的实心圆点形状不同；强制颜色下环与点都用 `CanvasText`。不再使用填色方块与问号、叹号字符。
3. 提示与可访问名称改为"等待你的输入"（Awaiting input），同时涵盖审批卡和提问表单。

## 不采用

- 完全照搬参考（等待与未读同为圆点、只差颜色）：违背架构第 8.2 节"不只靠颜色区分"的无障碍要求。
- 保留方形加问号：用户明确认为突兀，且与参考的安静标记语言不一致。
