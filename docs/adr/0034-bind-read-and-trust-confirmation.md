# 0034. 将读取记录和项目信任绑定到已完成的操作

- 状态：已接受（R2，维护者授权裁决）
- 日期：2026-11-19
- 修订：ADR-0027 第 1、4 条、ADR-0025 第 4 条的 Core 确认接口

## 背景

R2 在基线 `d57c72e` 核对了两个时间窗口。Read 在查询元数据时登记读过，之后内容读取或解析仍可失败。信任对话框在展示和确认时分别枚举项目，两个清单可能不同。

## 决策

1. Core 将文件版本、范围和工具调用作为待确认读取保存。只有该调用完成内容读取和解析才提交快照。失败、取消、版本不符与连接中断均丢弃待确认项。AHP 的 `fs/stat(read)` 开始暂存，成功送达与解析后由同一调用发 `fs/stat(read, completeRead: true)`，Core 核对初始内容哈希、路径、范围及已送达标记。
2. Core 返回与 checkout、工作目录及完整清单绑定的版本。肯定的信任决定必须提交用户看到的版本，Core 在持久化前核对，过期则返回最新视图并要求重新确认。拒绝和撤销始终可以执行。`decideProjectTrust(path, trusted, version)` 返回最新视图及 applied。过期的肯定决定不写库；客户端在新清单上重新确认。

## 取舍与验收

只在客户端再次比对不能约束 Core 保存的内容。只在读取失败后清除已读记录可能清除另一调用已经成功的记录。采用按调用提交能保持并发、取消和重试的一致性，代价是两端接口迁移。验收覆盖相同范围失败后重试、先读后改、不同调用乱序结束、过期与未变化的信任清单，以及拒绝操作。

## 重新评估的触发条件

若能通过现有契约证明同等的成功读取与展示时版本绑定，或协议需要支持跨版本并存，再评估迁移方案。
