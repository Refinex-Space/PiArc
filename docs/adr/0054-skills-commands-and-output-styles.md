# 0054. Skills、斜杠命令与输出风格的落地（补充）

- 状态：已接受，补充 ADR-0005、ADR-0025、ADR-0029、ADR-0033、ADR-0037、ADR-0039、ADR-0043、ADR-0048
- 日期：2026-11-21
- 相关：架构第 6.2.2、6.2.3、6.6.1、6.6.4、6.7、6.14、7.4、8.2、8.5、10.2 节；T37；FR-EX-01、FR-EX-02、FR-HN-07、FR-SY-05；登记事项 I02

## 背景

架构第 6.7 节定了方向：skills 遵循 Agent Skills 标准、在 Pi 默认路径之外读 `.claude/skills`、`~/.claude/skills`、`.piarc/skills`，system prompt 只列索引，`allowed-tools` 本回合免审批；斜杠命令合并内置命令、`.claude/commands`、Pi prompt templates 与 skills；输出风格可内置可自定义，切换以消息送达。Pi 1.5.2 自己也会加载 skills 与 prompt templates：它读 `<agentDir>/skills`、`~/.agents/skills`、`.pi/skills`、从 cwd 到 git 根的 `.agents/skills`、`<agentDir>/prompts`、`.pi/prompts`，把 skill 清单写进它自己的 system prompt 段、用 `/skill:名称` 展开，不读 `.claude/`、不认识 `allowed-tools` 与 `hooks`。T37 要定下基线没写到的细节：谁发现与解析、同名谁先、展开在哪里、`allowed-tools` 怎样进入裁决、skill 的 hooks 何时生效、模型怎样读 skill 的资源文件、输出风格存在哪里、会话中途的变化怎样送达。

## 决策

1. **发现与解析在 Core，Pi 自己的加载关掉。** `piarc_config::skills` 发现并解析 skills、命令文件与输出风格（单个文件至多 256 KiB），Core 的 `piarc_core::skills` 应答 Agent Host 的 `skills/list`。Agent Host 创建会话时传 `noSkills: true`、`noPromptTemplates: true`：Pi 不再加载这些资源，也不再展开 `/skill:名称` 与模板。理由与子 agent 定义相同（ADR-0048 第 1 条）：家目录、项目信任、权限规则、hooks 都在 Core，`allowed-tools` 与 hooks 的效果要由 Core 判断，Read 放行 skill 目录也要 Core 知道这些目录。
2. **来源与同名取舍。** 项目级优先于用户级；同级内 `.piarc` > `.claude` > Pi 默认目录；项目目录从会话 cwd 向上逐级查找（越近越优先，跳过家目录，与子 agent 定义相同）。skills 的来源依次为：`.piarc/skills/`、`.claude/skills/`、Pi 的项目目录（`.pi/skills/`、`.agents/skills/`）、PiArc 用户目录 `skills/`、`~/.claude/skills/`、Pi 的用户目录（`<数据目录>/pi/skills/`、`~/.agents/skills/`）。命令的来源依次为：`.piarc/commands/`、`.claude/commands/`、`.pi/prompts/`、PiArc 用户目录 `commands/`、`~/.claude/commands/`、`<数据目录>/pi/prompts/`。同名取第一份，后面的路径记进 `overrides` 并在设置页与诊断中列出。与 Claude Code 的差异：Claude Code 的个人 skill 优先于项目 skill，PiArc 与子 agent 定义、设置层一致，项目优先。插件来源（`resources_discover`、T40）与 MCP prompts（T40）在合并列表中预留来源，本任务不填。
3. **名称。** skill 是含 `SKILL.md` 的目录（递归查找，找到 `SKILL.md` 的目录不再向下；跳过以 `.` 开头的项与 `node_modules`），名称取 frontmatter 的 `name`，没有时取目录名；Pi 的两个 skills 目录另按 Pi 的规则把根目录下带 `description` 的 `*.md` 当作 skill。命令文件是 `commands/` 下的 `*.md`，名称为相对路径去掉扩展名、`/` 换成 `:`（`frontend/component.md` → `frontend:component`，与 Claude Code 相同）；Pi 模板取文件名。名称必须是 1–64 个字符，只含字母、数字、`-`、`_`、`.`、`:`，否则列为问题、不进列表。项目根以外的嵌套 skill（Claude Code 在处理子目录文件时加载）不在本任务范围，登记为后续。
4. **frontmatter。** YAML（与子 agent 定义同一个解析函数 `piarc_config::frontmatter`）；YAML 无效时与 Claude Code 一样仍加载，所有字段视为未设置并给出警告；`description` 缺省时取正文第一行非空文本。生效的字段：`name`、`description`、`when_to_use`（接在描述后进索引）、`argument-hint`、`arguments`、`disable-model-invocation`、`user-invocable`、`allowed-tools`、`paths`、`hooks`。解析但暂不支持的字段标 `unsupportedField` 并写明接手任务：`context`、`agent`、`background` → T48；`model`、`effort` → T48（I02：skill 的模型说明随 `context: fork` 一起评估）；`disallowed-tools`、`shell` 与其他字段标 `ignoredField`。命令文件支持同一子集（不含 `paths`）。正文中的 `` !`命令` `` 与 ```` ```! ```` 块不执行、原文保留，标 `dynamicCommand` 警告；Claude Code 的 `disableSkillShellExecution` 因此没有意义，列为忽略。
5. **参数替换。** `piarc_config::skills::args` 是唯一实现（Core 展开命令、`Skill` 工具加载正文都用它）：参数按 shell 规则切分（单双引号）；`$ARGUMENTS` 与 `$@` 是整段参数原文；位置参数 `$1` 起（Pi 模板与早期 Claude Code 命令的写法，第一个参数是 `$1`，缺少的为空）；`$ARGUMENTS[N]` 从 0 起（Claude Code 的写法，缺少的保持原文）；`arguments` 声明的名称按顺序对应参数（`$名称`，缺少的为空）；Pi 的 `${N:-默认}`、`${@:N}`、`${@:N:L}`、`${@:-默认}` 照 Pi 的语义；`\$` 转义紧跟的数字、`ARGUMENTS`、`@` 与声明的名称；参数值不再展开。正文没有任何占位接收参数而参数不为空时，在末尾追加一行 `ARGUMENTS: <原文>`（与 Claude Code 相同）。之后替换 `${CLAUDE_SKILL_DIR}`（SKILL.md 所在目录）、`${CLAUDE_SESSION_ID}`、`${CLAUDE_PROJECT_DIR}`（工作区根），`allowed-tools` 中的 `Bash(...)` 规则同样替换这几个变量。与 Claude Code 当前文档的差异：它的 `$N` 从 0 起，PiArc 按任务要求与 Pi 从 1 起。
6. **system prompt 第 5 段是索引。** 只列模型可调用的 skill：名称加描述（`description` 与 `when_to_use`，截断到 `SKILL_INDEX_DESCRIPTION_CHARS` = 1,536 字符，与 Claude Code 相同）；`disable-model-invocation`、`skillOverrides` 为 `off` 或 `user-invocable-only`、被 `Skill` 或 `Skill(名称)` deny 的不列，`name-only` 只列名称。带 `paths` 的 skill 先不列，Read、Write、Edit 成功处理了匹配文件（`piarc_config::rules::PathMatcher`，相对工作区根的 gitignore 语义，与 T24 的条件 rules 同一个匹配器，经 Core 的 `skills/match`）之后才以 `skillsChanged` 提醒列出，分支条目 `piarc.skillsActive` 记下已激活的（每会话一次，恢复与分叉沿用分支）。会话中途 skills 增删或描述变化时，下一次运行开始前以 `skillsChanged` 提醒送达差异，已发送的 system prompt 不改写；分支条目 `piarc.skillsIndex` 记下模型已知的索引。
7. **`Skill` 工具。** 规范名 `Skill`，参数 `{ skill, args? }`（与 Claude Code 相同）。它是只读工具：在任何模式下默认允许，`Skill`、`Skill(名称)`、`Skill(名称 *)` 的 deny 与 ask 照常生效。执行经 `skills/invoke`：Core 消费同一调用的授权（一次批准一次加载，ADR-0031），读取文件、完成参数替换，返回正文；正文作为工具结果留在对话中，Agent Host 写分支条目 `piarc.skillInvoked`（`{ name, content }`）供 T27 的重注入（单个 5K、合计 25K token）。同一回合内再次加载内容相同的 skill 只回答"已经加载"。`disable-model-invocation` 的 skill 经 `Skill` 调用得到错误结果。描述是 PiArc 自写的提示词。
8. **skill 目录对 Read 只读放行。** Core 在应答会话的 `skills/list` 时记下该会话可见 skill 的目录；裁决文件工具时这些目录与会话临时目录一样是只读目录：Read、Glob、Grep 读取不需要询问，写入仍按越界处理。模型由此可以直接读 SKILL.md 与资源文件（Agent Skills 的第三级）。
9. **斜杠命令的展开在 Core。** 客户端发送以 `/名称` 开头的输入时，Core 在 UserPromptSubmit hooks 之前查合并列表：内置命令不会到达这里（客户端执行）；命令与可由用户调用的 skill 由 `piarc_core::skills::expand` 展开为正文，`session/prompt`、`session/steer`、`session/followUp` 带上可选的 `command`（名称、类型、来源、参数与原文），Agent Host 在用户消息里记下原文与命令（界面显示 `/名称 参数`，模型收到展开后的正文），skill 另写 `piarc.skillInvoked`。不认识的 `/名称` 原样作为普通输入。展开之后是 T41 的 UserPromptExpansion 挂载点（`expand` 的 `ExpansionHook`，T37 为空实现）。UserPromptSubmit 看到的是用户输入的原文。
10. **`allowed-tools` 是回合级的 allow 规则。** 用户经斜杠命令调用、或模型经 `Skill` 调用一个带 `allowed-tools` 的 skill 或命令时，Core 把这些规则登记为调用所在会话当前回合的 allow 来源 `skill`（第 6.2.3 节第 6 步）：deny、ask、计划模式与受保护路径照常优先；回合完成、中断或连接断开时清除（与"仅本次允许"的授权同一处清理）。经排队的 follow-up 发出的命令不带这份授权（它开始的回合按普通规则询问）。项目来源（三类项目目录）的 skill 与命令只在项目受信任时产生这个效果，与项目的 allow 规则同等对待（第 10.2 节）：项目文件里带 `allowed-tools` 或 `hooks` 的 skill 与命令是可执行项，计入 `executables::enumerate`（名称加规则或 hooks 摘要），新增或改动即让项目回到未确认（ADR-0029、I63）。
11. **skill 的 `hooks` 从调用起到会话结束生效。** 与 Claude Code 相同：调用（斜杠或 `Skill`）后，frontmatter 的 `hooks` 作为限定在该会话的来源（层 `skill`）登记到 `HooksService`，会话关闭时撤下；同一会话可以叠加多个 skill 的 hooks，同一 skill 再次调用只登记一次。项目来源的要求项目受信任，否则不登记并在调用结果中说明。子 agent 定义的 hooks（ADR-0048）与 skill 的 hooks 共用同一张按会话的作用域表。
12. **输出风格。** 内置 `Default`（没有附加指令）、`Concise`、`Explanatory`、`Proactive`，指令文本由 PiArc 原创（`agent-host/src/harness/prompts/output-styles.ts`）。自定义风格是 Markdown 加 frontmatter（`name`、`description`；`keep-coding-instructions` 列为忽略：PiArc 的身份段始终保留；`force-for-plugin` 属于插件，T40），目录依次为 `.piarc/output-styles/`、`.claude/output-styles/`（cwd 向上）、PiArc 用户目录 `output-styles/`、`~/.claude/output-styles/`，同名取第一份；名称与内置风格相同的自定义风格被内置风格覆盖并列出。当前风格是设置键 `outputStyle`（与 Claude Code 同名同义，区分大小写，找不到时按 `Default` 并在诊断中列出），按设置层合并。`/output-style <名称>` 写 `.piarc/settings.local.json`（Claude Code 写 `.claude/settings.local.json`，PiArc 不写 `.claude/`），设置窗口写用户级 `settings.json`。新会话把风格指令放在 system prompt 第 3 段；会话中途风格变化时，下一次运行开始前以 `outputStyle` 提醒送达新指令，分支条目 `piarc.outputStyle` 记下已送达的风格，已发送的 system prompt 字节不变。
13. **内置命令。** Core 给出内置命令的名称、别名与参数提示（`/compact [重点]`、`/clear`（别名 `/reset`、`/new`）、`/model [模型]`、`/rewind`（别名 `/checkpoint`）、`/context`、`/output-style [名称]`），描述由客户端本地化；执行在客户端，只映射已有功能：`/compact` 是 T27 的压缩，`/clear` 在同一工作区新建会话（原会话保留在侧栏），`/model` 打开模型菜单或直接切换，`/rewind` 打开回退对话框，`/context` 打开上下文卡片，`/output-style` 打开风格菜单或直接切换。内置命令优先于同名的命令与 skill，冲突列出。
14. **AHP。** 能力 `skills`。Agent Host → Core：`skills/list`（会话或 cwd 的合并结果：skills、命令、自定义输出风格及其指令、当前风格、问题与覆盖）、`skills/invoke`、`skills/match`。Core → Agent Host：`resources/listSkills`、`resources/listCommands`（Agent Host 在 Core 的列表上合并自己的来源：插件与 MCP prompts 的预留位置）、`resources/reload`（Core 监听到 skills、命令、输出风格目录或设置的变化后发出，Agent Host 丢掉缓存，下一次运行开始前重新取）。`session/prompt`、`session/steer`、`session/followUp` 新增可选的 `command`；提醒类型新增 `skillsChanged`、`outputStyle`。Core API 新增 `listCommands`、`listSkills`、`setOutputStyle`；工作区没有运行中的 Agent Host 时，列表由 Core 直接回答。
15. **设置键。** Claude Code 的 `outputStyle` 与 `skillOverrides`（`on`、`name-only`、`user-invocable-only`、`off`）生效；`disableBundledSkills` 忽略（PiArc 没有随附 skill），`disableSkillShellExecution` 忽略（PiArc 从不执行 skill 中的命令）。

## 备选方案

| 方案 | 结论 | 理由 |
|---|---|---|
| 用 Pi 的资源加载器加上 `additionalSkillPaths` 读 `.claude/skills` | 否决 | Pi 不认识 `allowed-tools`、`hooks`、`paths`、`arguments`，不读 `.claude/commands` 的命名空间；它的 skill 段写进 Pi 自己的 system prompt，PiArc 用冻结的 system 时还要再拼一次；Core 仍然需要同一份列表来裁决与放行 |
| 展开斜杠命令放在 Agent Host | 否决 | `allowed-tools` 的授权必须由 Core 根据它自己读到的文件给出；在 Agent Host 展开就要让 Agent Host 声称"用户调用了某命令"，Core 无法核对 |
| skill 正文作为单独的 user 消息追加 | 否决 | 工具调用之后插入 user 消息会打乱角色交替（严格 mock 的 `role_order`）；正文作为工具结果同样留在对话中，并且天然归属于那次调用 |
| `$N` 按 Claude Code 当前文档从 0 起 | 否决 | 任务要求位置参数从 `$1` 起；Pi 模板与早期 Claude Code 命令都从 1 起，0 起会让 `$1` 静默错位 |
| 输出风格按会话保存 | 否决 | Claude Code 把它当作设置；按设置层保存时项目与用户都能给默认值，会话中途的切换经提醒送达 |

## 后果

- 正面：带 `.claude/skills`、`.claude/commands`、`.claude/output-styles` 的仓库打开即可使用；system prompt 只多一段索引；skill 的授权与 hooks 受项目信任约束；切换风格、增删 skill 都不改写已发送的 system prompt。
- 代价：Pi 包与 Pi 设置里 `skills`、`prompts` 路径指向的资源暂不加载（T40 与插件一起接入）；项目根以外的嵌套 skill 暂不加载；`$N` 的编号与 Claude Code 当前文档不同（L3 allowlist 记录）。
- 需要配套做的事：`context: fork`、skill 的 `model`/`effort`（T48）；UserPromptExpansion hook（T41）；插件 skills 与 MCP prompts 命令（T40）；嵌套 skill。
