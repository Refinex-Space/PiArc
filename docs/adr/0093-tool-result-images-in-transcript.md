# 0093. 工具结果图片进 transcript（补充）

- 状态：已接受（补充）
- 日期：2026-11-26
- 相关：ADR-0009 第 8 条（会话 blob）、ADR-0022（渲染进程安全）、PLAN 登记事项 I234；[设计增补 B2.7](../architecture/addenda/browser.md)

## 背景

工具结果里的图片字节只交给模型，transcript 条目只带文字（I234）。`Browser` 工具的截图是用户理解智能体在做什么的主要依据，必须在 transcript 里可见。

## 决策

1. 工具结果的图片在 Core 收到时写入会话 blob（内容哈希命名，`<数据目录>/sessions/<id>/blobs/`），transcript 条目带 `images[]`：`blob`（哈希）、`mediaType`、`width`、`height`；模型仍收到 image 块。
2. 渲染进程经现有短期预览地址机制取图（只读、按会话授权、过期失效），不经 `data:` URL；图片按缩略图显示，点击在对话框中放大。
3. 适用于 `Browser` 与 MCP 工具结果；Read 读取的图片保持按路径显示。
4. blob 随会话删除；诊断包不含 blob。

## 备选方案

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| 条目里内联 base64 | 简单 | 事件与会话索引膨胀；渲染进程处理大字符串 | 否决 |
| 只给模型不显示 | 现状 | 用户看不到智能体看到的画面 | 否决 |

## 后果

- 正面：用户与模型看到同一张截图；I234 关闭。
- 负面与代价：会话目录多一类文件，占用磁盘。
- 需要配套做的事：协议字段、`gen:protocol`、transcript 行渲染与 a11y 登记。

## 重新评估的触发条件

- 会话 blob 的磁盘占用超出第 11 章预算。
