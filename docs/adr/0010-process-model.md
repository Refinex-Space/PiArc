# 0010. 进程模型：每个工作区一个 Agent Host，子 agent 在进程内

- 状态：已接受
- 日期：2026-11-14
- 相关：架构文档第 3.3 节

## 背景

- 一个 Node 进程运行 Pi 约 120 MB RSS（Pi 调研实测）。每个会话一个进程时，5 个并行会话就是约 600 MB。
- Claude Desktop 被大量报告的内存问题中，相当一部分来自"每个会话的进程树常驻"和"stdio MCP server 按会话重复启动，每个约 1 GB"（anthropics/claude-code #76268、#99831，用户自报）。
- Pi 文档提到"一个进程运行多个会话，例如进程内子 agent"（`docs/environment-variables.md` 中 `PI_CODEMODE_MAX_WORKERS` 的说明）；coding-agent 中没有 `process.chdir`，cwd 按会话传递。但多会话同进程是否完全安全尚未实测。
- Claude Code 的后台会话架构是"supervisor 守护进程 + 每会话独立进程 + 空闲约 1 小时回收 + 崩溃自动重启"。

## 决策

1. **默认部署**：每个工作区（项目根目录）一个 Agent Host 进程，承载该工作区的所有会话（包括各自位于不同 worktree 的会话）。
2. **子 agent 在进程内运行**：用 SDK 创建子会话，不再 spawn 新的 Pi 进程。
3. **MCP server 按工作区共享**：PiArc 用自己的 MCP 扩展替换 Pi 内置 MCP 扩展（内置扩展是 replaceable），在 Agent Host 内维护一个共享连接池，同一工作区内每个 MCP server 只启动一份，按需启动、空闲回收。
4. **生命周期由 Core 监管**：按需启动、预热；工作区内所有会话空闲超过阈值（默认 30 分钟，可配置）后回收进程，会话已落盘，需要时恢复；崩溃后自动重启并恢复会话，未完成请求按 ADR-0009 标记为 uncertain。
5. **AHP 从第一天起按会话多路复用**（每条消息带 `sessionId`），因此可以随时退回到"每会话一个进程"，Core 和协议都不用改。

## 备选方案

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| 每会话一个进程 | 隔离最好，崩溃影响面最小，与 Claude Code 后台会话同构 | 内存随会话数线性增长；MCP 难以共享 | 作为退路 |
| 全应用一个 Agent Host | 内存最省 | 一个工作区的问题会影响所有项目；不同项目的信任与扩展配置混在一起 | 否决 |

## 后果

- 正面：多会话的增量内存成本低；MCP 不随会话数膨胀，这是相对 Claude Desktop 可量化的差异点。
- 负面与代价：一个进程崩溃会中断该工作区的全部会话（可恢复）；需要排查 Pi 中的进程级全局状态（例如凭据读取缓存、codemode worker 上限）。
- 需要配套做的事：M0 验证同一进程内两个不同 cwd 的会话并发运行，覆盖工具执行、压缩、中断、MCP；把 `PI_CODEMODE_MAX_WORKERS` 纳入配置。

## 重新评估的触发条件

- M0 或之后发现无法规避的跨会话状态串扰；
- 单进程崩溃率高到影响体验（例如每 100 会话小时超过 1 次）。
