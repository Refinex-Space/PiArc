# 0040. Windows 上无需用户参与的权限裁决预算

- 状态：已接受（2026-11-19，用户在 W1 会话中采纳）
- 日期：2026-11-19
- 修订：架构第 11 章"无需用户参与的权限裁决"一行（p95 ≤ 2 ms）的 Windows 口径
- 相关：T20-A13、W1、[ADR-0031](0031-basic-permissions.md)、[ADR-0036](0036-bind-file-operations-to-directory-handles.md)、`crates/piarc-core/src/tool_io/policy/tests.rs` 的 `automatic_decision_latency`

## 背景

第 11 章要求无需用户参与的权限裁决 p95 ≤ 2 ms。macOS 实测 p95 0.43–0.53 ms（T20、T21），Windows 一栏为"未测"。W1 第一次在 Windows 实测：

| 环境 | p50 | p95 | p99 |
|---|---|---|---|
| CI `windows-latest`（运行 44453549786，`cargo test --workspace` 中与其他测试并行） | 2.37 ms | 3.35 ms | 6.21 ms |
| W1 实机（i5-1340P、NVMe、Defender 实时保护开启，单独运行，三次） | 3.8–5.7 ms | 8.4–8.9 ms | 10.1–10.4 ms |

用临时计时拆开一次典型裁决（约 3.2 ms，`tmp/evidence/W1/policy-latency-breakdown.log`）：

- 规范化工作区路径 0.1 ms；
- 解析 git checkout 0.3 ms；
- 读四层设置 0.2 ms；
- 项目信任查询约 0.9 ms：再解析一次 checkout，查 SQLite，扫描可执行项清单；
- 定位目标路径与判断边界 0.45 ms；
- 捕获目标目录的身份绑定 0.75 ms（ADR-0036）；
- 审计写入与线程切换约 0.3 ms。

耗时分散在几十次文件元数据调用上，没有单一热点。NTFS 加上 Defender 的过滤驱动，每次打开或查询约 50–150 µs，是 APFS 的 5–10 倍。ADR-0031、0036 要求每次裁决都按当时的磁盘状态判断（设置、信任清单、目录身份），所以这些调用不能简单省掉。即使把设置与信任改为按监听结果缓存，只剩路径定位与目录绑定也约 1.2 ms，再加上尾部抖动，p95 仍会超过 2 ms。

这项测试也是 `cargo test` 的一部分，所以 Windows 上的 `npm run verify` 与 CI 的 `verify (windows-latest)` 因它失败。

## 决策

1. 第 11 章这一行按平台给预算：macOS 保持 p95 ≤ 2 ms；Windows 为 p95 ≤ 10 ms。两者都包含路径规范化、设置、信任、目录绑定与 SQLite 审计，口径不变。
2. `automatic_decision_latency` 按运行平台断言对应预算，打印的测量值不变。不新增跳过条件。
3. 不改变每次裁决读取最新磁盘状态的语义（ADR-0031、0036）。
4. 优化交给后续任务，不在 W1 做：
   - T23 重写权限规则时，同一次裁决内只规范化和解析 checkout 一次（现在设置与信任查询各做一遍）；
   - T23 评估按设置监听（`workspace_settings`）与信任变化广播失效的缓存；
   - T44 把两个平台的这项测量纳入性能回归，并按实测复核 Windows 预算能否收紧。

## 备选方案

- **在 W1 中实现缓存，保持 2 ms**：设置与信任按工作区缓存，由文件监听和信任广播失效。监听事件有去抖与投递延迟，期间的裁决会用到旧设置，这是新的语义，需要单独评审；而且按上面的拆分，只靠缓存也到不了 2 ms。
- **复用目录绑定**：违反 ADR-0036"实际操作绑定当时获准的目录身份"，不采用。
- **只在 Windows 上把测试移出 `cargo test`**：等于让 Windows 不检查这项预算，属于削弱测试，不采用。

## 后果

- Windows 上自动裁决多出的几毫秒落在一次工具调用之前，相对模型往返和命令执行可以忽略，用户感知不到。
- 一个预算出现两个平台口径。第 11 章已有同类先例（R1 校准 Windows 的事件循环与回显口径）。

## 重新评估的触发条件

- T23 的优化落地后，Windows 实测 p95 降到 2 ms 以内；
- 权限路径新增每次裁决都要做的文件系统操作（例如 T23 的 Bash 分析读取文件）；
- Windows 用户反馈工具启动有可感知的延迟。
