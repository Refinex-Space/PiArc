# 0051. 终端面板与渲染器：会话终端的归属、输入防线、停拉唤醒与选区在 Core（补充）

- 状态：已接受，补充 ADR-0017 第 3、4 条、ADR-0023、ADR-0050 第 5 条
- 日期：2026-11-20
- 相关：架构第 6.11、8.2、8.3、8.5、10.3、11 章；T34；FR-TL-05；登记事项 I30、I51

## 背景

S7 的结论是走正式路线：渲染进程按 `requestAnimationFrame` 拉 Core 的帧、用 fork 的 Canvas 渲染器绘制（ADR-0017、ADR-0023）。T33 定稿了帧协议、输入编码、读屏与会话终端。T34 交付面板时要回答几件基线没写到的事：

- 面板的终端属于谁。T10 原型的终端归创建它的页面所有，页面重载即关闭；面板要求重载后恢复、shell 不受影响，而会话终端在 T33 已是会话的后台任务。
- 第 10.3 节登记的差距（I51）：终端输入不经 Core 的权限裁决，渲染进程被注入时可以借它执行命令；每窗口的终端数与在途拉帧没有上限。
- 空闲时怎样不轮询。按 rAF 拉帧意味着可见的空闲终端每秒拉 60–120 个空帧；第 11 章要求空闲 CPU 接近 0、无轮询。
- 选区、滚动、链接放在哪一侧，怎样与按键保持顺序。
- 终端的默认颜色怎样跟随设计令牌，且程序查询到的颜色与画面一致。

## 决策

1. **会话终端归会话，不归页面。** 面板只经 `openSessionTerminal` 打开会话终端（T33 的 `terminal` 类任务）。主进程把它们登记为会话终端：任何窗口都可以查看与输入，页面重载、渲染进程崩溃或窗口关闭都不关闭它们；它们在关闭标签、会话归档或删除、应用退出时随任务结束。重载后面板从 `core/tasks` 快照找回终端，第一次拉帧以 RESET 帧恢复整屏。没有会话的终端只能由开发构建的测试钩子创建，仍归页面所有；`window.piarc` 不再有 `createTerminal`（I30 的终端函数部分收口）。
2. **输入防线：近期真实输入。** 主进程从窗口创建起记录 Electron 的 `input-event`（键盘、鼠标按键与滚轮、触摸；不含指针移动），这些事件来自系统输入，页面脚本无法伪造。写入类命令（`terminalInput`、`terminalKey`、`terminalPaste`、鼠标按下与松开）、打开会话终端与切换共享，都要求该窗口在 5 秒内有过真实输入，否则拒绝。上限：每个会话至多 16 个打开的终端；每个窗口对每个终端至多一个在途拉帧请求。这是收紧，不放宽第 10.3 节的基线。
3. **停拉与唤醒。** 视图连续收到 8 个空帧后，下一次拉帧带 `park`：Core 在持终端锁时记下唤醒标记，若该帧仍为空视图就停止拉取、停止 rAF；之后第一段输出到达时 Core 在 `term/<id>` 发一次 `output` 事件，视图恢复拉取。输入、调整尺寸、滚动、焦点变化也会唤醒。标记在锁内设置，所以帧与标记之间到达的输出不会被漏掉。帧仍只作为拉取请求的返回值送达（ADR-0023 不变），`output` 事件不携带画面。
4. **不可见即不拉。** 面板关闭、标签不可见、页面隐藏、窗口最小化或隐藏时不拉帧。Playwright 驱动的 Electron 中最小化窗口的 rAF 仍在运行，所以主进程以应用事件 `visibility` 报告窗口的最小化、隐藏、恢复与显示，视图据此停拉。
5. **选区、滚动与链接在 Core。** piarc-term 暴露 libghostty-vt 的选区手势（按下、拖动、松开；双击选词、三击选行由渲染进程的点击计数决定；Shift 扩展）、选区文本（formatter，合并折行、去行尾空格）、视口滚动与单元格的 OSC 8 链接。指针事件与按键走同一个写线程，保持先后顺序：程序跟踪鼠标时交给鼠标编码器，否则（或按住 Shift 的左键）作为选区手势；滚轮在主屏滚动 scrollback，在备用屏且开启 1007 时发方向键。键入会回到底部并清除选区。帧按行带回选区列，渲染进程不保存选区状态。普通 URL 由渲染进程在帧的行文本里识别；打开任何链接都经主进程的确认框，只放行 `https:`、`http:`、`mailto:`。
6. **默认颜色取设计令牌。** 组件令牌 `terminal.*`（背景、前景、光标、选区、查找匹配与当前匹配）是终端的主题；视图把前景、背景、光标交给 Core 作为终端的默认颜色（`terminalSetColors`，经写线程），所以没有自身颜色的单元格和程序的 OSC 10/11/12 查询都得到同一组值；ANSI 调色板仍是 libghostty-vt 的终端调色板。
7. **渲染器按设备像素绘制。** fork 的 `CanvasRenderer` 以设备像素度量字体与格子、不做 `scale`，小数缩放比下格子落在整像素；Core 收到的格子尺寸与指针坐标也是设备像素。改动清单在 fork 目录的 README。
8. **键盘归属。** 终端获得焦点时按键都交给终端，只有快捷键注册表中标为 `global` 的命令（Ctrl+\` 切换终端面板、Ctrl+Tab、Mod+,）留给应用；macOS 的 ⌘ 组合键不进终端。复制：macOS ⌘C；Windows Ctrl+Shift+C，或有选区时的 Ctrl+C（无选区时 Ctrl+C 发给程序）。粘贴经浏览器的 paste 事件交给 Core，由 Core 按程序的 bracketed paste 包装；可能直接执行的文本先在面板里确认。

## 备选方案

| 方案 | 结论 | 理由 |
|---|---|---|
| 会话终端仍归页面，重载后重新打开 | 否决 | shell 与正在运行的程序会随重载结束，违反"重载后 shell 不受影响" |
| 以文档例外接受终端输入不经裁决 | 否决 | 属于放松安全基线；近期真实输入的检查成本低，覆盖"无人操作时被注入"的情形 |
| 终端输入也走 Core 的权限裁决 | 否决 | 用户在自己的 shell 里打字就是执行命令，逐键裁决没有意义 |
| 空闲时降低拉帧频率 | 否决 | 仍是轮询；降频还会推迟后台程序输出的显示 |
| Core 主动推送帧 | 否决 | 违背拉取模型（ADR-0017 第 3 条、ADR-0023）；推送通道在按键后被推迟 |
| 选区在渲染进程按帧的单元格计算 | 否决 | scrollback 中的选区要随输出滚动，复制要用 formatter 的折行规则；libghostty-vt 的选区是被跟踪的状态，帧已能带回 |
| 渲染进程只替换颜色、不告诉 Core | 否决 | 程序查询 OSC 11 会得到与画面不同的背景（vim 据此选配色） |
| 无障碍改用 wterm 的 DOM 渲染器 | 不采用 | S7 评估需要改掉 `innerHTML` 并绕开它的按键编码；第一版用"以文本查看屏幕"提供 Core 读屏的文本 |

## 后果

- 新增 Core API：`terminalScroll`、`terminalClearSelection`、`terminalSelectionText`、`terminalLinkAt`、`terminalSetColors`，`terminalFrame` 的 `park`，鼠标事件的 `clicks`；协议类型 `TerminalEvent::Output`、`TerminalScroll`、`TerminalLink`。
- 新增 IPC 13 个、去掉 `createTerminal`（`window.piarc` 共 86 个）、应用事件 `visibility`；主进程的终端命令都经 `TerminalOwners` 核对归属、真实输入与上限。
- 测试与自动化必须用真实输入路径（Playwright 的键盘、鼠标）驱动终端；在页面里直接调用 `window.piarc.terminalInput` 会被拒绝。
- 空闲或不可见的终端不跑 rAF、不拉帧；输出到达后一个 IPC 事件唤醒。

## 重新评估的触发条件

- Electron 或 Chromium 不再为脚本无法伪造的输入发 `input-event`，或出现能伪造它的途径。
- 多窗口同时查看同一终端成为常态（每个终端一个 viewer，换 viewer 发 RESET 帧，T35 评估）。
- 屏幕阅读器用户反馈"以文本查看屏幕"不够用（再评估 DOM 镜像或 wterm）。
