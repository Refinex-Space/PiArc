# 0032. 服务商设置、凭据更新与会话选型（补充）

- 状态：已接受，补充 ADR-0006、ADR-0021 与 ADR-0026
- 日期：2026-11-19
- 对应任务：T21

## 决策

1. 用户可以先配置服务商再打开工作区。Core 为设置操作启动短生命周期的 Agent Host，在应用数据目录下工作，仅允许其调用 Core 的保险箱服务。设置 Host 通过 Pi 的 `ModelRuntime.login` 和 `logout` 更新凭据，再由 `CoreCredentialStore` 经 AHP 持久化。返回客户端的配置包含凭据是否存在，编辑已有配置无需回显密钥。
2. 用户级设置保存服务商标识、类型、协议、端点、模型 ID 列表与云认证方式。Core 将自定义模型定义投影到隔离的 `pi/models.json`，无密钥端点使用公共占位值使 Pi 将其列为可用。有密钥的自定义连接将凭据绑定到实际协议和端点，更换目标时需要提供对应的密钥。
3. 跨文件变更由 Core 串行执行。写入前在 `agent-host/provider-change.json` 记录不含密钥的变更意图。凭据写入携带变更标识。进程中断后，Core 对照保险箱确认凭据更新是否已经落盘，完成对应的模型定义和用户设置投影，再删除日志。删除服务商同时清理保险箱条目。
4. 模型目录和会话选择由持有该会话的 Host 回答。切换前向 Pi 查询当前上下文用量，根据目标模型的缓存写入价格估算美元费用，模型定价缺失时显示未知。以提供商、API、模型 ID 三者判定已有助手 thinking 块在下一次请求中的保留情况。用户确认后由 Pi 写入模型和 thinking level 会话条目。
5. Core 的凭据锁记录连接身份。服务端检查请求截止时间，客户端在持锁操作期间续期。连接断开或租约过期后拒绝新写入，已获准的写入结束后再释放占用的键。

## 依据

Pi v1.5.2 自定义提供商支持声明模型 ID 和兼容协议。第三方服务商账号的可用模型取决于套餐与地域，所以模型目录允许手填，联网刷新沿用 Pi 的目录缓存策略。百炼端点与锁定版本的源码依据见 [Pi 调研](../research/pi-v1.4.0-baseline.md#t21-自定义提供商线协议与可用模型v152)。

设置 Host 让首次启动和已有工作区使用同一套 Pi 认证适配，同时保留 Core 对保险箱的独占写入。持久化变更意图解决了用户设置、保险箱和 Pi 配置无法一起原子替换的问题。
