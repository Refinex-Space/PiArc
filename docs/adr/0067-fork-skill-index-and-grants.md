# 0067. 隔离执行的 skill 如何显示在索引中、如何取得授权

- 状态：提议
- 日期：2026-11-23
- 涉及：T48-A06，[ADR-0054 第 4、9、10、11 条](0054-skills-commands-and-output-styles.md)

## 背景

普通 skill 省略 `description` 时，Core 从正文提取第一行非空文本，最多 250 个字符。Agent Host 把描述加入 system prompt 的 skill 索引。因此，一个只有一行正文且没有描述的 `context: fork` skill，在调用前就能将整段指令送入父会话。调用时，现有实现还把正文留在父会话的工具结果或输入中，供压缩后恢复。

普通 skill 的 `allowed-tools` 在调用所在会话的当前回合生效，`hooks` 登记在该会话直至关闭。隔离执行时调用者是父会话，实际执行者是子会话。按原规则接入，会让父会话在该回合使用给子任务的授权，并可在子任务结束后继续触发其 hooks。

## 提议

1. 对 `context: fork`，父会话的索引只取显式的 `description` 和 `when_to_use`。两者都缺省时索引只列名称。普通 skill 的摘要回退仍按 ADR-0054 第 4 条处理。
2. 用户经斜杠命令或模型经 `Skill` 调用时，正文只作为隔离子会话的任务交付。父会话记录调用名称、参数和执行结果，重注入与排队也遵守正文隔离。子会话使用 skill 选定的 agent 类型，按其工具过滤和权限边界执行。[官方行为说明](https://code.claude.com/docs/en/skills#run-skills-in-a-subagent)
3. Core 在用户输入或已批准的 `Skill` 调用上确认该次启动与执行者。只有实际执行的子会话才可使用这次调用的 `allowed-tools` 和 `hooks`。继续检查来源与项目信任，普通权限规则照常裁决。子会话结束时撤下作用域，启动失败、拒绝或中断的调用不得遗留可供其他会话使用的授权。

## 取舍与验证

显式填写描述的 skill 仍可按用途自动发现；没有描述的隔离 skill 仅能按名称发现。验收覆盖没有描述的单行正文、前后台调用、子会话授权以及父会话后续请求，比较 mock 实际收到的内容与工具裁决。若保留现有回退和授权归属，需要重新规定 A06 允许父会话看到的正文，以及父会话何时可以使用子任务的权限。
