# 0036. 将文件操作绑定到获准的目录对象

- 状态：已接受
- 日期：2026-11-19
- 修订：ADR-0027 第 2、5 条的目录检查及文件访问方式

## 背景

路径规范化、先读后改和审批确定了允许访问的名称。其他进程仍能在批准与打开、写入与提交之间移动目录。工作区归档后，相同路径上重新创建的工作区应获得独立授权。

## 决策

1. Core 在普通文件工具预检时记录规范路径、用途以及目标最深的现存目录对象。对话框上的批准适用于该目录下的原请求。工作区、额外目录、会话只读目录也保留各自的目录对象。不存在的下级目录可以在已有授权范围内逐级创建。
2. `piarc-fs` 使用精确锁定的 `cap-std`、`cap-fs-ext` 4.0.3。合法的符号链接先依规则规范化，随后从已授权目录描述符按单组件打开，过程中拒绝新出现的链接。文件读取、编码检测和摘要使用打开的文件；目录身份不符或无法取得时拒绝操作。Unix 用非阻塞模式打开并确认普通文件，避免等待特殊文件的写入者。
3. 原子写入、提交和失败清理共享同一开放目录。Unix 以相对目录描述符执行 rename，提交前复核目录身份。若外部进程恰好在最终身份复核与 rename 之间移动该目录，提交仍作用于原目录对象；Unix 没有同时提交命名空间检查与目录内 rename 的事务。临时文件始终属于该目录。
4. Glob、Grep 与文件提及从已绑定目录遍历，工作区 ignore 规则和搜索读取共享目录权限。额外获批的单个文件使用对应文件权限，外部目录搜索从该目录开始。
5. Windows 以卷与文件标识核验目录。相对打开经库的句柄 API，目录打开时禁止共享删除。库的 Windows 路径转换会去掉 verbatim 前缀，不能直接用于 UNC 上的列举、目录创建、原子提交或清理。这些操作保留原始规范 UNC 或驱动器路径，先逐级持有禁止共享删除的目录句柄并核验目标目录，保持到操作结束。工作区启用期间，Windows 可能直接阻止重命名。代码保持 safe Rust，架构 7.1 的 unsafe 范围无需扩展。

## 后果与重新评估

保留了编码、换行、目标权限、精确审批与合法链接的行为；代价是额外目录句柄和身份查询。Windows 真实 UNC 共享、长路径、NTFS 重解析点及共享删除行为由 W1 实机复核。若需要支持无法提供稳定文件标识的文件系统、ReFS 的 128 位标识，或标准库提供完整的跨平台句柄相对操作，再评估此封装。
