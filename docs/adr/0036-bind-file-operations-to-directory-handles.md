# 0036. 将文件操作绑定到获准的目录对象

- 状态：提议
- 日期：2026-11-19
- 拟修订：ADR-0027 第 2、5 条的路径检查及文件访问方式，架构 7.1 的平台封装范围

## 背景

当前操作先取得获准的规范路径，再以路径打开文件或执行替换。独立进程可在两步之间改变目录结构。会话间的路径锁不能约束独立进程。此问题涉及读写、搜索遍历与临时文件提交，仅在写入前重复比较路径不能关闭时间窗口。

## 提议

保留现有审批目标与受保护目录规则，把授权解析结果绑定到稳定的目录对象。优先评估两平台可用、许可证兼容的安全封装，验证已批准的链接、目录迁移和 Windows 重解析点语义；如果确实需要原生调用，在 piarc-fs 的单独平台模块中封装并收窄 unsafe 例外。文件打开、创建和最终提交经同一授权对象完成，无法确认对象身份时停止。用户需要确认这一依赖或平台封装范围，特别是 Windows 原生验证及现有链接行为。

## 后果与重新评估

代价是跨平台实现与实机测试。能力依赖目录位置时，目录被移动后的授权应失效。验收采用临时目录与无敏感内容的夹具，验证原目录、已授权链接、目录变更和失败后的原文件保留。若标准库提供完整的跨平台目录句柄相对操作，再评估去除封装。
