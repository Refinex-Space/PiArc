# 0029. 客户端外壳的基础设施：令牌管线、偏好存储、快捷键、本地化、信任闸门与会话元数据（补充）

- 状态：已接受（补充 ADR-0013、ADR-0025，T18）
- 日期：2026-11-18
- 取代：无
- 相关：架构文档第 7.6、8.2、8.3、8.5–8.8、9.2、9.3、10.2、10.3、11 章；ADR-0006、ADR-0011、ADR-0013、ADR-0018 第 6 条、ADR-0025

## 背景

T18 做出用户第一眼看到的客户端，同时给之后所有界面打底：设计令牌、偏好设置、快捷键、本地化、通知，以及会话列表需要的 Core 命令。架构第 8 章写了规则（令牌分层、单一来源、ICU MessageFormat、快捷键可自定义、通知与计数），没有写这些东西放在哪里、谁是写入方、用什么库。

实现中还暴露了两处与信任有关的空白：

- 登记事项 I63：信任之后新增的可执行项在用户确认前已经生效。`trust/get` 只看决定，不看决定时的快照。
- 信任决定会让工作区的 Agent Host 重启。原来的重启由订阅广播的任务异步触发，信任对话框之后立即创建的会话会落到正在关闭的旧进程上，以 `shuttingDown` 失败。决定发生在 Agent Host 还在启动时也一样。

## 决策

1. **设计令牌的单一来源是 `design/tokens/*.json`，分四层加尺度**：`palette.json`（原始色，每个色族 12 级明阶梯与 12 级暗阶梯）→ `ramps.json`（角色 → 色族，例如 `accent: indigo`）→ `semantic.json`（语义色，引用 `<角色>.<级>` 或固定色，可按四种模式分别给值，另含强制颜色映射）→ `component.json`（组件令牌引用语义令牌或尺度），`scale.json` 放系统字体栈、字号、圆角、动效与两档密度。`npm run gen:tokens`（`scripts/dev/gen-design-tokens.mjs`）生成 `apps/desktop/src/renderer/theme/tokens.generated.css` 与 `apps/desktop/src/shared/design-tokens.ts`。verify 的"design tokens"步骤检查四件事：
   - 生成物与源文件一致；
   - `contrast.json` 声明的每一对前景 / 背景在四种模式下都达到 WCAG（正文 4.5:1、大字与界面组件 3:1，高对比度模式正文 7:1）；
   - 品牌规则：主色色族中饱和度不低于 0.2 的颜色，HSL 色相不在 10°–50°（橙色、陶土色）；表面色不是暖奶油色；字体栈不含 Anthropic 字体与衬线字体；
   - 资源清单：应用源码、打包与 `design/` 下没有字体文件、音频文件，也没有以其他品牌命名的图标。

   改视觉方向只改令牌，组件只读语义层与组件层。D3 未定之前，主色色族是中性的 indigo（临时），由视觉关口请用户确认。
2. **客户端偏好写在用户级 `<数据目录>/settings.json`，Core 是唯一写入方**：`language`、`appearance`（`theme`、`contrast`、`density`、`reduceMotion`）、`keybindings`（命令 id → `Mod` 记法，只存覆盖值）、`notifications.enabled`。读写都经 `piarc_core::client_settings`。写入经 `piarc_config::write_value`，只接受这四个顶层键。主进程读取一次；修改时先校验，再经 Core 写入，然后把新偏好发给每个窗口。窗口布局等呈现状态留在各窗口的 localStorage，不进设置文件。
3. **本地化用 intl-messageformat 12.1.4**（BSD-3-Clause，`@formatjs/*` 依赖为 MIT）。它解释执行消息 AST，不用 `eval`，渲染进程的 CSP 不放宽。英文目录是消息 id 的来源，简体中文目录的类型必须覆盖全部 id。主进程（菜单、原生对话框、通知）与渲染进程共用 `src/shared/i18n/`。语言偏好为 `system` 时，取系统首选语言中第一个能匹配的。
4. **快捷键注册表在 `src/shared/keybindings.ts`**（命令 id、默认键、标签消息 id）：
   - 渲染进程按 `KeyboardEvent.code` 匹配有效绑定，所以布局与 Shift 不改变按键；匹配后执行命令并 `preventDefault`，输入法合成中不匹配。
   - 主进程菜单显示同一份绑定作为加速键；菜单点击经应用事件发给窗口执行。
   - 冲突按平台换算后的物理按键判断：`Mod+W` 与 `Ctrl+W` 在 Windows 上冲突，在 macOS 上不冲突。
   - 只有 Mod、Ctrl、Alt 组合或功能键可以绑定。
5. **信任闸门（I63）**：信任决定为"信任"、且当前没有快照之外的新增可执行项时，项目才算受信任。`StoreLookup` 与 `TrustView.trusted` 用同一判断，所以 `trust/get` 在用户确认新增项之前答"不信任"。删除的条目不需要再确认。
6. **信任变化的重启在应答之前生效**：`decideProjectTrust` 与 `revokeProjectTrust` 记下决定后，调用 `Hub::trust_changed`，同一主 checkout 的工作区 actor 先把状态置为 `Restarting`，再请监管器重启，然后才返回结果。之后的请求等新进程就绪。决定发生在首个进程启动期间时，工作区等待重启之后的那个代次。客户端因此在信任对话框之后可以立即创建会话。
7. **会话元数据是 Core 自己的状态**：
   - 用户标题存在 `sessions.custom_title`（schema v2），置顶、归档沿用 v1 的列，重建索引时都保留；标题的优先级是用户标题 > Pi 的会话名 > 首条用户消息。
   - 会话打开期间的修改先记在会话 actor 里，随下一次索引同步写入。Pi 在第一条回复之后才写文件，此前索引里没有该行。
   - 归档时，打开的会话先关闭，再删除 `<数据目录>/sessions/<id>/`（第 9.3 节）。
   - 删除时先关闭会话，让 Agent Host 停止写文件，再删除 Pi 的 JSONL（只删 `pi/sessions/` 之下的文件）、会话临时目录与索引行。
   - 删除前的确认在主进程的原生对话框里：页面只能请求删除，不能跳过用户的点击。
8. **需要用户处理的会话由渲染进程判断，主进程负责通知**：
   - 状态徽标的优先级与"需要处理"的定义集中在 `src/renderer/store/status.ts`（出错、等待审批、完成未读；归档的不算）。
   - 窗口是否在前台由主进程告知（`focus`、`blur` 应用事件）。`document.hasFocus()` 在自动化与某些窗口排列下不可靠。
   - 会话开始需要处理、而它不在前台显示时，窗口总给应用内提醒，主进程同时 Dock 弹跳（macOS）或闪烁任务栏（Windows），窗口不在前台且通知开启时另发系统通知。macOS 上程序无法知道横幅是否真的出现（S6、I43），所以前两项不省略。
   - 计数显示为 Dock 角标；Windows 上显示为任务栏覆盖图标（一个状态色圆点，描述文字为数量）。

## 备选方案

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| 令牌直接写在 CSS 里 | 少一个生成步骤 | 主进程拿不到颜色（窗口背景、标题栏覆盖层）；对比度与品牌无法在 CI 中检查 | 否决 |
| @messageformat/core | 功能相同 | 编译消息会生成函数，需要 `unsafe-eval` 才能在渲染进程里用 | 否决 |
| 偏好由主进程直接写设置文件 | 少一次跨 NAPI 调用 | 设置文件出现两个写入方，与 `piarc-config` 的写入约定冲突 | 否决 |
| 菜单加速键负责全部快捷键 | 一处实现 | Windows 的隐藏标题栏下没有菜单栏；自动化测试的按键不经过原生菜单；渲染进程无法在输入法合成时拦截 | 否决 |
| 闸门放在各消费者：只启用快照内的条目 | 已确认的条目照常可用 | hooks、MCP、allow 规则、插件、扩展各自实现一遍，容易漏 | 否决：整个项目受限直到确认，对话框只列新增项，确认成本低 |
| 信任决定也在主进程弹原生确认框 | 渲染进程被注入时不能静默信任项目 | 用户要连点两次；审批卡（T20）同样在渲染进程作答 | 暂不做，登记 I79 由 T45 评估 |

## 后果

- 正面：
  - 视觉方向只改令牌；对比度与品牌回退会让 verify 失败；
  - 所有界面字符串都经同一份目录；
  - 快捷键在设置里改后，窗口与菜单立即生效；
  - 信任对话框之后创建会话不再失败，新增的可执行项在确认前不生效。
- 负面与代价：
  - 一个新增条目（例如 `git pull` 带来的 hook）会让整个项目受限，直到用户确认；
  - 渲染进程能做出信任决定（I79）；
  - verify 多一步（约 1 s）。
- 需要配套做的事：
  - T43 做缺失翻译检查与全面无障碍；
  - T20 在会话快照里加 `pendingApprovals`（渲染进程已按它计算"等待审批"）；
  - T35 处理关闭窗口后的通知与菜单栏图标；
  - 视觉关口确认后，D3 落实为令牌。

## 重新评估的触发条件

- 用户在视觉关口或之后调整视觉方向：只改 `design/tokens/`，检查脚本的品牌规则随 D3 更新；
- T45 评估 I79 后决定给信任决定加原生确认；
- 需要第三种语言：评估按需加载目录。
