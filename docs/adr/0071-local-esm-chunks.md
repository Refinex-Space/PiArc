# 0071. 将 Agent Host 的可延迟模块打成随应用分发的本地 ESM 分块

- 状态：已接受（2026-11-24，按本次 M4 收尾授权作出的变更型决策）
- 修订：架构第 5.6 节的单文件构建约定。沿用 ADR-0015 第 4 条的 asar 外布局、内置 Node 和现有 AHP 入口。
- 关联：R5-A02、I194、I222

## 背景

在 M1 Max、32 GB 的 Mac 上，同一个开发包、同一个本地 mock、相同的预热与采样窗口，单活动会话的 Agent Host RSS 中位数为 206.44 MB，预算为 150 MB。将 esbuild 产物仅作语法和空白压缩后为 173.44 MB。保留标识符并将动态导入输出为本地 ESM 分块后为 140.18 MB。两种实验均对开发包副本重新封签，使用原有会话探针，使用相同的内置 Node。原始报告在 `tmp/evidence/partial-closure/nightly-initial.json`、`host-single-session.json` 和 `host-chunk-session.json`。

## 决定

1. Core 仍启动 `agent-host.mjs`，该文件静态导入带内容哈希的入口模块。esbuild 输出到同目录下的 `chunks/`，按原有模块的静态、动态导入决定何时加载。全部 JavaScript 随安装包离线分发。依赖白名单、包资源、沙箱与进程边界沿用现有规则。
2. 构建从 esbuild 的完整输出生成 `bundle-files.json`，记录入口、各模块的文件名及 SHA-256。先发布完整的带哈希模块，再原子替换清单和启动文件。已有开发会话可能稍后才导入旧模块，开发目录保留这些模块。
3. 打包只复制同一份清单列出的模块，以该清单生成稳定入口。布局检查比对入口文本、每个模块的 SHA-256 和文件总数。分块放在 `app.asar` 外，并沿用最终应用的签名与发布完整性校验。

## 代价与复核

构建、打包及缺文件诊断需要识别多个模块。开发目录会保留旧哈希，在关闭开发会话后可以清理生成目录。升级 Node、Pi 或 esbuild 时，验证本地冷导入、登录、MCP、扩展、两平台安装包布局和会话内存。第 11 章的预算、回归阈值和已有基线保持原值。
