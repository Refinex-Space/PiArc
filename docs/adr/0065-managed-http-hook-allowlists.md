# 0065. 管理员可以独立限定 HTTP hook 的目的地址与请求头变量

- 状态：已接受
- 日期：2026-11-23
- 修订：[ADR-0055](0055-websearch-and-hooks-m3.md) 第 8 条的列表合并规则
- 关联：[T47 设计增补](../architecture/addenda/T47-auto-memory-and-managed-settings.md) 第 5、6、8 节，R4 登记事项 I169

## 背景

HTTP hook 向匹配的地址发送事件，请求头可以引用 handler 明确列出的环境变量。T38 交付时没有企业设置层，两份白名单都按列表并集合并。沿用这一行为时，即使管理员给出空名单，受信任项目、用户或会话仍可以加入条目。项目信任表达的是用户同意运行项目配置，企业策略还需要单独限定它的权限。

## 决策

1. 分别判断 `allowedHttpHookUrls` 和 `httpHookAllowedEnvVars`。当管理员配置其中一个键，有效值取设置该键的最高优先级托管来源的整份列表。更低托管来源和普通设置层均不能添加条目。
2. 空列表有效。地址名单为空时禁止 HTTP hook 发请求，变量名单为空时所有请求头变量都按现有规则替换为空串。托管名单类型或元素类型有误时，记录诊断并把该来源的这份名单按空列表处理。
3. 管理员未设置的键沿用 ADR-0055 的合并规则。移除托管键后，在下一次策略刷新时恢复普通层的合并值。handler 自身的变量名单继续参与交集判断。
4. 在 `piarc-config` 合并时实施规则。hook 执行器、配置诊断、托管锁定视图和设置写入都使用同一结果。

## 备选与后果

保留所有列表的并集会让下层扩大管理员的授权。额外增加一个托管专属开关会让管理员同时维护名单和开关。采用逐键接管后，管理员可以只限定目的地址，或只限定环境变量。依靠多个来源共同补充同一名单的部署，需将允许项汇总到最高优先级来源。

## 重新评估的触发条件

如果需要让不同管理员独立维护互相约束的名单，重新评估托管来源间的交集或委派规则。
