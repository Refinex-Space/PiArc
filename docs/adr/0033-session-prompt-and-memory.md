# 0033. 会话提示词快照与外部 memory 导入（补充）

- 状态：已接受
- 日期：2026-11-19
- 相关：ADR-0004、0005、0006、0026、0031；架构第 6.6、6.15、7.4、9.1、9.2、10.2 节

## 决策

1. Core 在创建会话时采集开场 memory 与 git 状态。Git 只输出分支和文件状态，限制 32 KiB，截断时标记。开场快照禁用外部过滤器和文件系统监视器，依赖 clean 过滤器的工作区可能与终端显示的状态有差异。需要审批的文件等首个回合有可交互的会话后读取。等待确认期间已经读到的开场文档保留原版本。
2. Harness Kit 在 Pi 1.5.2 的 `before_agent_start` 中组装七段，将完整文本设置为 `systemPromptOptions.forceSystemPrompt`。M1 生成第 1、2、4、7 段。会话分支的 `piarc.systemPrompt` entry 保存第一次发送的文本、日期和各来源内容摘要。Pi 重放分支时可恢复精确前缀。升级前创建的会话在首次使用此能力时建立快照。
3. 用户 memory 先读 `~/.claude/CLAUDE.md`，再读数据目录下的 `MEMORY.md`。此后逐级读取从文件系统根到会话 cwd 的固定文件。每级依次处理 `CLAUDE.md`、`.claude/CLAUDE.md`、适用时的 `AGENTS.md`、`CLAUDE.local.md`。同目录存在两个主文件时由 `memory.readBoth` 控制。测试使用隔离的家目录。
4. Core 用会话所属工作区及导入的规范目标确定权限。固定 memory 名称经符号链接指向其他外部文件时也要确认。权限扩展沿用 T20 的账本、取消、连接代次和“总是允许”的原生确认。持久许可写入 Core 数据库的 `memory_imports`，仅对该工作区展开该文件有效。权限卡上的精确规则只读。拒绝在导入处保留目标路径及用户填写的反馈。普通工具的可访问目录与项目可执行项信任仍由各自的权限流程管理。
5. Host 经协商能力 `memory` 调用 `fs/memory`。Core 从已注册的会话取得根目录，自行发现来源。扫描与审批卡绑定回合，迟到的上一回合结束通知只清理所属回合；用户中断或会话断开会撤销当前扫描。同一快照的后续页绑定连接、请求标识与 UTF-8 偏移，一页至多 1 MiB。这样多个合法的 4 MiB 文件也可以通过 8 MiB AHP 帧。
6. 实际完成的文件工具调用提供访问目录。搜索工具交回格式化、截断前的命中路径。首次进入子目录和已加载文件发生变化分别触发 `piarc.memory` custom message，标记与来源可在模型请求中辨认。首条输入比会话创建晚时同样能收到期间变化。Anthropic 将工具结果及 custom message 都编码为 user 角色，因此该线格式把相邻消息中的 memory 放在同一 user 消息的后续文本块中。会话文件保留原始条目。

## 依据与代价

Pi 的 `forceSystemPrompt` 在调用服务商前投影实际发送的 system 文本。SDK 在 transcript 中单独保存其结构化工具声明。使用公开扩展接口即可保留工具恢复能力，同时让 PiArc 拥有提示词与来源加载顺序。每回合重新读取已发现的文件可检测原子替换、删除以及导入内容变化。读取与解析在 Core 的阻塞线程池进行。

## 重新评估的触发条件

T24 接入条件 rules、T27 接入压缩或 Pi 升级改变 custom message 的送达位置、system 投影、服务商缓存断点时，重新验证原始模型请求、审批隔离与恢复后的字节一致性。
