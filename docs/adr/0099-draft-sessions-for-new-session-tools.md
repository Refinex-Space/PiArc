# 0099. 新会话页的工具与草稿会话

- 状态：已接受（补充）
- 日期：2026-11-27
- 取代：无
- 相关：架构文档第 7.6 节（实体快照）、第 8.2 节（信息架构）；ADR-0051（终端归会话）、ADR-0052（worktree）、ADR-0075（工具分块）、ADR-0076（项目文件）

## 背景

右上角的文件、终端、Changes、预览都以会话为单位：终端按 ADR-0051 归会话，项目文件、`gitRequest`、`browser` 的参数也都是会话 id。新会话页在发出第一条消息之前没有会话，所以这些工具都不出现，用户要先发一条消息才能看文件、开终端。Claude Desktop 有同样的限制，公开的功能请求还没有答复；Codex 的文档写明终端"范围是对话所在的项目或 worktree"，worktree 在发出第一条提示时才创建，没有说明发消息之前能否用这些工具。

## 决策

1. 新会话页照常显示工具。用户第一次打开某个工具（或用它的快捷键）时，Core 在该项目里建一个草稿会话（`createDraftSession`，工作目录是项目根），工具都绑定它；第一条消息发给这个会话，已经打开的工具保留。
2. 草稿是普通会话，加一个标记：会话句柄与 actor 共享，第一条输入（prompt、steer、follow-up）被 Core 接受后清除。`core/sessions` 的条目带 `draft: true`；客户端的会话列表（侧栏、搜索、命令面板、"下一个会话"）不列出草稿，工具按 id 照常读取它；活动计数不计草稿。
3. 新会话页离开草稿时丢弃它（`discardDraftSession`，与删除会话相同，结束它打开的终端），包括：切到别的会话、换项目、选择 worktree。Core 只丢弃仍是草稿的会话，已经接受过输入的会话一律拒绝，所以任何迟到的丢弃都删不掉对话。
4. 主进程按窗口记录它建的草稿，页面重载、崩溃或关闭时丢弃这些草稿（依赖第 3 条的拒绝，转正的会话不受影响）。应用退出时草稿没有会话文件（Pi 在第一条回复时才写），重启后不存在。
5. 选择 worktree 时工具不可用并说明原因：worktree 在发出第一条消息时才创建（与 Codex 一致），没有可以绑定的目录。
6. 工具面板的范围按视图划分：会话视图按会话 id，新会话页是一个范围。草稿出现时新会话页不重建（保留已选的模型、模式与 worktree 设置）；发出第一条消息后按会话 id 恢复已打开的工具。新会话页的右栏默认收起，用户按右栏按钮时才展开。
7. 草稿建好之前，用户点的工具立即以"准备中"的分块出现（按钮为按下且 `aria-busy`），草稿建好后在同一次提交里换成工具本身；关掉准备中的分块或再点一次按钮即取消，草稿建好后不再打开它；建草稿失败时分块消失。离开新会话页、换文件夹或选 worktree 时一并撤下。（补充，2026-11-27：首次点击要等 Agent Host 建会话，点击后需要立即的反馈。）

## 备选方案

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| 进入新会话页就建草稿 | 打开工具不用等 | 每次点"新建会话"都建一次会话 | 不采用 |
| 工具改为按项目工作，第一条消息后把终端交给会话 | 不建会话 | 改多个 Core 接口的范围和 ADR-0051 的终端归属，属于变更型 | 不采用 |
| 渲染进程自己隐藏草稿 | 不改 Core | 其他窗口与托盘计数仍会看到它 | 不采用 |

## 后果

- 正面：发消息之前就能看文件、开终端、看 Changes 与预览，从文件列表拖入提及；第一条消息之后工具不中断。
- 负面与代价：每个用过工具的新会话页多一个 Agent Host 会话；应用退出时草稿里终端的后台任务记录留在 `background_tasks`，显示为已中断。
- 需要配套做的事：Core 端到端（草稿列为草稿、首条消息后转正、丢弃结束终端、拒绝丢弃对话）、主进程归属单测、渲染进程的 hook 与 store 单测、L4 `home-tools.e2e.ts`、preload 白名单与 S10 报告。

## 重新评估的触发条件

- 工具改为可以按项目工作，或终端的归属改变。
- 新会话页需要在 worktree 模式下预览 worktree 的内容。
