# 0066. fork 子会话继承父会话的工具声明

- 状态：提议
- 日期：2026-11-23
- 涉及：架构第 6.4、6.15 节，T48-A04、A05，[ADR-0048 第 4 条](0048-subagents-and-model-aliases.md)

## 背景

ADR-0048 要求子会话从模型请求中隐藏只属于主会话的工具，并在深度上限隐藏 `Agent`。目前 `hidingOthers` 和 `toolGate` 使用同一份工具集合。T48-A04 要求 fork 首次请求的工具定义与父会话最近一次请求逐字节一致，以便复用缓存。即使只有一个工具声明被隐藏，发往服务商的前缀也会改变。[Claude Code 的 fork 行为](https://code.claude.com/docs/en/sub-agents#fork-the-current-conversation)

## 提议

1. 允许 fork 子会话继承父会话已发送的 system 和工具声明，保留声明顺序、描述、参数与缓存标记。仅对继承历史的 fork 开放这条例外。以指定 agent 在独立上下文运行的 skill 沿用该 agent 的工具筛选。
2. 工具能否执行仍按子会话权限判断。即使父会话声明了提问、模式切换、自动记忆等主会话专用工具，fork 调用它们时也要被拒绝。达到深度上限的 `Agent` 调用以及 fork 再次请求 fork，均应在启动子会话前得到错误。其他调用继续在 Core 按当前权限裁决，并沿用主会话审批与检查点。
3. 验收分别检查声明与执行。mock 对比父子请求的 system、工具定义和消息前缀；行为用例验证主会话专用操作被拒绝、嵌套 fork 被拒绝且没有新建会话，合法编辑仍可审批和回退。

## 取舍

采纳提议可保留共享缓存，但模型可能尝试一个只能在父会话中执行的工具，由闸门返回拒绝原因。维持 ADR-0048 对所有子会话的隐藏规则则需要调整 A04 对逐字节一致的要求。把父会话的执行权限也完整交给 fork 会改变现有交互与权限边界，本提议保留这些边界。
