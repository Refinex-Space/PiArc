# 0035. 工具命令可继承的环境

- 状态：提议
- 日期：2026-11-19
- 拟修订：ADR-0028 第 3 条中的环境继承约定

## 背景

T17-A08 和架构 6.11 要求命令环境不含凭据。ADR-0028 规定以登录环境为基础，过滤内部变量，不加入应用凭据。当前代码满足后一个约定，但会继承用户已经导出的环境变量。变量名和内容均由用户或其他软件决定，按已知密钥名称过滤不能提供前一个保证。

## 提议与代价

对模型发起的 Bash 和 PowerShell 使用相同的环境准入原则。只继承启动 shell、操作系统与工具链定位所必需的已审核字段（例如 PATH、临时目录、locale、Windows 系统目录），其中路径字段只作为路径处理。工具命令默认失去第三方凭据及任意自定义构建变量；需要凭据的工作流须另提授权设计。PiArc 保险箱保持独立。避免从命令启动脚本重新导入父环境。不能承诺任意子进程无法自行读取用户文件，沙箱属另一层控制。

另一选择是维持 ADR-0028 的继承语义，把架构与验收明确限定为应用管理的凭据；用户已导出的密钥仍可能被命令读取。该选择涉及安全承诺，须由维护者决定。

## 重新评估的触发条件

凭据化工具链、Windows 安装差异或沙箱接入要求新增环境字段时重新核对。用合成变量验证登录环境、回退环境与 Windows 分支。
