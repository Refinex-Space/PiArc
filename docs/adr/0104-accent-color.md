# 0104. 外观设置里的强调色

- 状态：已接受（用户在 2026-11-27 选定预设、默认色与自定义方式）
- 日期：2026-11-27
- 修订：ADR-0006 与架构第 8.6 节的"主色避开橙色 / 陶土色系"，改为只约束默认强调色；T18 视觉关口确认的 indigo 主色改为"蓝色"预设
- 相关：ADR-0029（设计令牌）、ADR-0101（设置是工作台里的视图）；[视觉规范](../engineering/visual-design.md)

## 背景

主按钮、开关、焦点环、选中底色和链接都读 `accent` 阶梯，T18 起固定为 indigo。用户希望像 ChatGPT 的设置面板一样在"外观"页选择强调色，选中后全应用的按钮与开关一起变化，并提出：预设与 ChatGPT 一致（含黄色、橙色），支持用系统取色器自定义，默认用石墨而不是蓝色。

## 决策

1. **预设**写在 `design/tokens/accents.json`：默认（石墨）、蓝色、绿色、黄色、粉色、橙色、紫色。每个预设指定代替 `accent` 阶梯的色族，并可覆盖少数语义值：石墨在深色模式下是浅色实底配深色文字、链接仍用蓝色（`link` 阶梯）；黄色配黑色文字；绿色用 `emerald`（成功色阶梯，实底加深到能配白字）。
2. **生成器**把默认预设写进 `:root` 与各 `data-color-mode` 块，其他预设只写有差异的 9 个令牌（`ACCENT_TOKENS`），选择器是 `[data-accent][data-color-mode]` 加没有模式属性时的媒体查询回退；强制颜色块的选择器与它们同特异度且排在最后，系统色仍然生效。verify 对每个预设、每种模式检查全部对比度对（74 对 × 4 模式 × 7 预设）。
3. **品牌规则只约束默认强调色**：色相 10°–50° 的检查只看 `ramps.accent`（即默认预设）。用户主动选的橙色、黄色等预设不受限制。
4. **状态色不随强调色变化**：运行中、未读的状态点与提交图的第 0、5 条泳道改读 `link`（indigo），保持原来的颜色。
5. **自定义**：偏好 `appearance.accent` 取预设 id 或 `custom`，`appearance.accentColor` 是 `#rrggbb`（PiArc 用户 `settings.json`，Core 的 schema 只认这两个形状）。外观页的色块打开系统取色器，旁边可直接输入十六进制。渲染进程（`app/accent.ts`）按 `ACCENT_PAIRS` 修正：实底在画布上至少 3:1，实底上的文字取黑或白，悬停与按下向远离文字的方向加深，选中底色淡到正文与状态点仍达标，链接 4.5:1、焦点环 3:1。规则经构造的样式表只作用于浅色与深色模式，并包在 `@media not (forced-colors: active)` 里；高对比度模式与强制颜色继续用默认强调色。弹出的工具窗口同步 `data-accent` 与样式表。

## 备选方案

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| 只给预设，不支持自定义 | 每种颜色都经 verify 检查 | 不满足用户要求 | 不采用 |
| 自定义色原样使用，不修正 | 和用户选的完全一致 | 浅色或很暗的颜色会让按钮文字、链接、焦点环不达标 | 不采用 |
| 默认保持 indigo | 不改已有截图 | 用户明确要求默认石墨 | 不采用 |

## 保留的风险

- 橙色预设或自定义的橙色、陶土色会接近 Claude 的品牌色。这是用户主动的选择，默认色与产品界面本身不使用这些色相，品牌检查仍对默认色生效。
- 自定义色修正后，按钮上显示的颜色可能比用户选的略深或略浅；十六进制输入框保留用户输入的值。
