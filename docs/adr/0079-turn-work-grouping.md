# 0079. 回合过程的合并与收起

- 状态：已接受（取代 ADR-0078 第 6 条"生成中的思考块强制展开"与架构第 8.2 节同一句）
- 日期：2026-11-25
- 来源：用户在会话主块对标中的追加要求（"思考块默认不展开""处理过程在正文开始或回合结束后收起"）
- 相关：ADR-0022、0030、0045、0078；架构第 8.2 节

## 背景

一个回合在正文之前常有多段思考与工具调用。原规则把思考块单独成行并在生成中强制展开，命令（Bash）与网页搜索也各自成行，于是思考、命令、编辑交替排成一长串，正文被推到很远。参考实现在默认视图里隐藏思考，一段连续的工具调用只占一行摘要，正文出现后才落成摘要。

## 决策

1. **一段过程是一组。** 同一回合里连续的工具调用和夹在其间的思考合成一个工具组；正文、用户消息、自带卡片的行（任务、计划、提问、下一步、子 agent）或新回合结束这一段。只有思考、没有工具调用的一段仍是单独的思考行。命令与网页搜索也进组，组内仍以各自的卡片显示。
2. **运行中展开，之后收起。** 组是运行中回合的最新内容（后面只有待审批卡与 working 行）时默认展开，实时列出步骤；正文开始或回合结束后默认收成一行摘要。用户手动展开或收起后，以用户的选择为准。
3. **思考默认折叠。** 思考块在生成中也默认折叠，标签显示"正在思考…"并走光，用户可以随时展开；结束后显示"思考了 N 秒"。普通视图仍不显示思考（ADR-0045 第 9 条不变），思考档仍是默认视图。
4. **摘要。** 摘要按动作计数（读取、搜索、编辑、运行命令、网页搜索……），读取、编辑、获取网页按不同对象计数，只有一个对象时写出对象；超过四段时显示前三段加"另外 N 项"。思考不计入摘要。增删行数与最差结果放在末尾。

## 影响

- 只改渲染进程的分组与展示（`store/transcript.ts` 的 `relist`、`transcript/rows/tools.tsx`、`summary.ts`、`messages.tsx`），Core、Agent Host 与 AHP 不变。
- 依赖"命令卡独立成行"或"思考生成中展开"的 L4 用例改为先展开所在的组，断言不变。

## 不采用

- 参考的"运行中只在组头显示当前调用"：PiArc 在运行中直接展开步骤，回合结束后再收起，过程更透明。
- 把思考时长写进组摘要：摘要只说做了什么，思考在展开后查看。
