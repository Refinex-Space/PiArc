# 0068. 由 hook 创建的工作目录如何登记和清理

- 状态：已接受（2026-11-23，用户委托本次 T48 会话裁决）
- 日期：2026-11-23
- 涉及：T48-A07、架构第 6.12 节、[ADR-0052](0052-worktrees-search-and-desktop-integration.md) 第 1、3、4 条

## 背景

T48 要求 WorktreeCreate 返回目录，WorktreeRemove 接管它的移除。Claude Code 的接口也支持非 Git 版本控制系统。ADR-0052 要求工作区为 Git 顶层，目录和分支有固定位置，归档和子会话结束时通过 Git 判断能否安全清理。若直接接受任意 stdout 路径，Core 会把该路径用作文件工具的工作根。若把无法检查的目录视为干净，定时清理可能丢弃用户改动。

## 决策

- 维持工作区内的文件边界。创建 hook 可以返回工作区内 `.piarc/worktrees/` 的直接子目录。Core 核对规范路径、目录身份与归属，拒绝主 checkout、其他会话的目录以及经链接逃离该位置的路径，错误时保留现场。
- 登记由 hook 创建的目录及所属工作区。移除时重新按当前信任和设置选择 WorktreeRemove。替代操作执行失败时报告原因，保留记录以便重试。禁止退回递归删除或强制执行 Git 清理。
- 普通 Git worktree 继续按 ADR-0052 判断未提交改动、保留分支。对于无法经 Git 判断改动的 hook 目录，子会话结束或归档到期时保留目录，由用户明确确认移除后才调用移除 hook。创建与移除的结果均经真实目录状态核对。
- 初版保留目录约束。支持工作区外目录会扩大文件工具、沙箱和项目信任的边界，需要另行设计。该兼容差异登记在架构与测试说明中。

## 验证

覆盖普通 Git 生命周期、成功的 hook 创建与删除、任意非零退出、输出路径越界、失去信任、已归档目录有改动，以及无法核实目录所有权时保留现场。
