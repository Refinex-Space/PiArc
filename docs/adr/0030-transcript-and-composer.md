# 0030. 会话输入、附件和 transcript 的呈现（补充）

- 状态：已接受
- 日期：2026-11-18
- 修订：ADR-0029 第 7 条的归档清理范围（用户在 T19 确认）
- 相关：ADR-0009 第 8 条、ADR-0011、ADR-0013、ADR-0022、ADR-0026，架构第 5.3、7.4、7.6、8.2–8.5、9.3 节

## 背景

模型需要图片字节、PDF 的内容和文件的相对路径。用户在对话中看到的是自己写的正文、文件名和附件胶囊。两种表示都需要随会话恢复。T18 归档时清理整个会话临时目录，而 T19 的历史消息可能继续引用其中的附件。

## 决策

1. Core 定义命令清单、文件匹配和附件限制。渲染进程从 `composerInfo()` 读取命令的 `name`、`source`、`action` 和描述，包括 `/clear`（回到当前工作区的新建会话页）、`/compact`（空闲会话的独立压缩回合）、`/help`（命令与快捷键）。`searchFiles` 在已知工作区内按忽略规则枚举文件，返回相对路径、名称和匹配位置。每个输入框使用独立的搜索 ID，新查询取消同 ID 的旧查询。
2. 编辑器的提及节点保存 `{id, label, path}`，显示 `@label`。发送时用 `@path` 生成文本，并记录 `{path, start, end}`，区间按 UTF-16 码元计算，含起点、不含终点。`session/prompt`、`session/steer`、`session/followUp` 都可携带提及和附件。T14 的 NAPI 文本入口继续接受任意正文，包括恰好能解析为 JSON 的正文。结构化输入使用独立的 NAPI 方法 `promptInput`、`steerInput`、`followUpInput`，主进程按 preload 透传的实参类型分发。
3. 发送前，渲染进程将附件通过主进程交给 Core 的 `storeAttachment`。Core 校验内容签名和大小，以 SHA-256 和经校验的扩展名写入 `sessions/<id>/attachments/`。原始文件名仅用于显示。输入与事件只携带 `InputAttachment`（种类、显示名、MIME、blob 引用和可选页数），Core 核对引用属于本会话。工具对附件目录只有读权限。
4. 归档时关闭会话、清理临时输出并保留 `attachments/` 和 Pi JSONL。这样取消归档后，历史消息仍能引用原附件。用户删除会话时，Core 删除整个会话目录（含附件）、会话 JSONL 和索引行。
5. Agent Host 为 Pi 准备模型输入。锁定的 pi-ai 1.5.2 在 `UserMessage.content` 中只接受文本与图像块。图片经 blob 读取后作为图像块发送。PDF 复用 T16 的 `fs/pdf`，发送前 20 页以内的提取文本，剩余页可用 Read 的 `pages` 参数读取。每次实际交付输入时，在用户消息前写 Pi 的 `piarc.input` 自定义条目保存 `turnId`。带附件或提及的输入还保存用户正文和胶囊元数据。手动压缩的条目记录 `{turnId, action: "compact"}`。
6. 运行中的重试次数来自 `turn/retrying`，用量来自每次回复结束时的 `turn/usage`。Agent Host 对终态错误分类，在 `turn/completed` 提供 `errorKind` 和 `retryable`。客户端对未送达的输入复用原 `requestId` 重发。已失败或被 Core 标为 `uncertain` 的回合由用户发起新回合重试。幂等记录位于打开的 Agent Host 会话内，进程中断时由 Core 的未决调用机制提示用户。
7. 历史与实时事件汇入每个会话的 `SessionTranscript`，由同一组 React 行组件呈现。`session/resync` 后重新读取历史窗口，整段替换已确认的行，保留乐观输入。Pi 的历史 entry id 与实时文本块 id 可以不同。前翻分页按历史条目补到列表头，切换到已缓存会话直接使用其 store。历史条目的可选 `turnId` 让 steer 留在原回合、follow-up 成为新回合。旧文件缺少回合标记时，历史投影按最近一条用户消息的 entry id 分组。

## 备选方案

| 方案 | 取舍 |
|---|---|
| 仅记录发给模型的消息 | 展示已提取的 PDF 正文会掩盖用户原本的输入，单靠字符串也无法恢复提及的位置。 |
| 在每次输入和事件中传附件字节 | 会重复传输大块数据，还可能超过 AHP 帧上限。会话引用可以复用同一份文件。 |
| 归档时清空整个会话目录 | 附件引用会失效。T19 据用户决定缩小清理范围。 |

## 后果

每次输入最多 10 个附件，支持 PNG、JPEG、GIF、WebP（每个最多 5 MiB）和 PDF（每个最多 32 MiB）。历史记录可保留展示所需的元数据，归档附件继续占用磁盘空间，直到删除会话。文件枚举最多收集 200,000 个文件，在超大目录中结果可能不完整，调用方可读取 `truncated` 标记。

## 重新评估的触发条件

- pi-ai 新版本支持原生文档内容，或模型能力表能给出更具体的输入限制。
- 附件生命周期需要跨会话共享、独立保留期限，或历史投影需要跨分支同步元数据。
- 文件匹配的枚举量或真实会话渲染超出第 11 章预算。
