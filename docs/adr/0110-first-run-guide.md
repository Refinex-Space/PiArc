# 0110. 首次运行的欢迎屏与连接模型

- 状态：已接受（用户在 2026-11-28 确认设计增补 `docs/architecture/addenda/first-run.md`）
- 日期：2026-11-28
- 相关：ADR-0006（clean-room）、ADR-0021（凭据只在保险箱）、ADR-0073（桌面前端以 OpenClaudeDesktop 为参考）、ADR-0083（连接测试与模型列表）、ADR-0107（服务商品牌标记）、ADR-0109（用户级偏好的先例）

## 背景

新装 PiArc 后直接落在新会话页。这个页面没有空状态，模型按钮显示"自动模型"，唯一的入口是模型菜单最底下的"配置服务商"。用户要等到发送消息时才看到报错。

参考实现 OpenClaudeDesktop `next-4.16336.0` 的首次运行分三屏：欢迎、选择 agent、连接模型。PiArc 只有 Pi 一个 harness，服务商由 Pi 的内置目录提供，另有账号登录、自定义与本地端点，连接测试与模型列表在 ADR-0083 已经落地。

## 决策

1. **两步引导**：全窗口的引导层，依次是"欢迎"（放大的方块吉祥物、字标、一句副标题，按钮"开始设置 / 稍后设置"）和"连接模型"（左侧快速设置宫格，右侧是所选项的表单）。没有"选择 agent"，也没有单独的"选择项目"。引导层是 `Shell` 的兄弟节点，打开期间工作台 `inert`，渲染进程的快捷键不生效。设置打开时引导层隐藏但不卸载，代理设置往返后状态还在。
2. **宫格**：一格是一个服务商家族（DeepSeek、智谱 GLM、Kimi、通义千问、MiniMax、小米 MiMo、OpenAI、Anthropic、Gemini、OpenRouter），家族的地区与套餐变体是 Pi 各自的内置 id，在右侧的"地区与套餐"里选。中文界面先列国内家族、默认选国内变体，英文界面先列海外家族、默认选国际变体。家族表只写 id，运行时与 `builtinProviders` 取交集，目录里没有的变体不显示，一个变体都没有的家族不显示。另有"账号登录"（`loginProviders`，不含 Claude.ai 订阅）、"更多服务商"（现有 `ServiceChooser`）、自定义端点与本地模型。
3. **测试并继续**：先 `saveProvider` 后 `testProvider`，与设置页同一条路径，不新增 Core、AHP、NAPI 接口和 IPC。测试失败时凭据保留在连接列表里，界面给出原因和"跳过测试"，网络类失败另给"代理设置"。登录成功等同于测试成功。
4. **密钥**：密钥只存在于连接步骤的表单 state 中。切换宫格、切换变体、修改地址或协议、离开这一步时都清空；不写进存储、地址、偏好或提示。"获取密钥"的地址写死在 `onboarding/key-links.ts`，只收 https，经主进程的外链确认打开。
5. **完成标记**：用户级偏好 `onboarding.completed`（Core 的 `CLIENT_KEYS` 与 `piarc_config` 的 schema 新增 `onboarding`，主进程的 `pointerOf` 只接受 `true`）。`preferencesFrom` 满足任一条件就推导为已完成：标记为真、`modelProviders.providers` 非空、`modelProviders.accounts` 非空。完成、跳过测试和"稍后设置"都写这个标记。写入被托管设置拒绝时，本次运行照样关闭引导层。
6. **自动出现**：同时满足三点才出现：未完成；第一份 `core/workspaces` 快照里没有工作区；这个窗口不是因为启动目标（链接、拖入文件夹、第二次启动）打开的。第一份快照到达之前，未完成的窗口先盖一层空白，避免新会话页闪一下。偏好会广播到所有窗口，自动打开的引导在任一窗口完成后都会关闭。
7. **再次进入**：设置"模型与服务商"的"连接"一节有"快速设置…"；新会话页打开了项目、模型目录为空时，模型按钮变成"连接模型"。两处都直接打开"连接模型"一步，这时"返回"按钮写作"关闭"，Esc 也会关闭。
8. **测试**：L4 的基础夹具预写 `{"onboarding":{"completed":true}}`，整份覆盖 `settings.json` 的用例合并它（`L4_USER_SETTINGS`），生产代码不加测试开关。内置服务商的测试会连真实厂商，所以保存后测试的路径在组件测试里覆盖。L4 的成功路径用回环上的 OpenAI 兼容桩服务（自定义端点）与 mock 授权服务器（登录）。

## 备选方案

- **按 `providerSettings()` 判断是否出现**：每次调用都要起停一个设置 Agent Host，冷启动时太慢；它也看不到经 `pi/models.json` 配置的模型。不采用。
- **新增"测试未保存的配置"**：要改 AHP、Agent Host、`Operation`、NAPI、IPC、preload 快照与 L1 样本。设置页本来也是不校验就保存。不采用。
- **测试失败时自动删除刚保存的服务商**：删除要经主进程的原生确认，会在引导里多弹一个对话框；凭据留在连接列表里，可以测试或删除。不采用。
- **用环境变量在 L4 里关掉引导**：发布构建里就多了一个隐藏开关。不采用。
- **保留"选择 agent"一步**：PiArc 只有 Pi 一个 harness。不采用。

## 后果

- 新用户第一次打开就能在一屏内连上模型；老用户（有服务商、账号或工作区）升级后不会看到引导。
- 保留风险：ADR-0083 之前只经 OAuth 登录（账号不在 `modelProviders.accounts`）、又没有任何工作区的用户，升级后会看到一次欢迎屏，点"稍后设置"即可。
- 保留风险：测试失败或跳过测试后，没通过的密钥留在保险箱里，要在设置里删除。
- 设置打开在引导层之上时（主菜单的"设置"、代理设置），引导层隐藏，关闭设置后回来。
- 家族表与 Pi 目录可能漂移：升级 Pi 时，`families.test.ts` 用当时的内置 id 做快照，会提醒。
