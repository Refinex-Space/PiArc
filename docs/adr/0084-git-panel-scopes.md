# 0084. Git 面板的数据来源与范围（取代 ADR-0044 第 8 条）

- 状态：已接受（用户在 2026-11-25 的会话中选定"Git 为主 + 保留本会话"）
- 日期：2026-11-25
- 取代：ADR-0044 第 8 条（Changes 面板）
- 相关：ADR-0044、0060（行内评论）、0073（对标 Claude Desktop）、0075（工具分块）、0078（只呈现已有能力）、0085、0086；架构第 6.9、7.6、7.7、8.2 节；[设计增补](../architecture/addenda/git-panel.md)

## 背景

ADR-0044 第 8 条让 Changes 面板只显示会话检查点：基线是本会话第一次写入前的内容，只覆盖经 Core 写入的文件，按文件或 hunk 丢弃时核对版本。Bash 产生的改动、用户自己的修改、已经提交的工作都不在其中。

Claude Desktop `next-4.16336.0` 的 Changes 面板读 Git：默认范围是当前分支相对基础分支 merge-base 到工作区的全部改动（含未跟踪文件），可换成"未提交改动"（HEAD 到工作区）或单个提交；基础分支依次取会话记录的、`origin/HEAD`、`main`/`master`、当前分支；不在 Git 仓库时退回会话自己的改动；面板没有丢弃按钮（`app/src/diff-scope-model.mjs`、`app/electron/git-status.cjs:297-348`）。

用户要求把【改动】面板与之逐项对齐，并扩展为完整的 Git 工具；在审视时确认保留会话检查点视图。

## 决策

1. **四种范围。** Git 仓库内面板提供：全部改动（默认，`merge-base(基础分支, HEAD)` → 工作区，含未跟踪文件）、未提交改动（HEAD → 工作区，含未跟踪文件；空仓库以空树为基线）、单个提交（`<sha>^` → `<sha>`）、本会话改动（ADR-0044 第 8 条原有的检查点视图，计算方式不变）。非 Git 目录只有本会话改动。
2. **基础分支。** 依次取 worktree 会话的创建基础分支、`origin/HEAD`、`origin/main`、`origin/master`、本地 `main`、本地 `master`、当前分支；用户在"比较对象"里选的分支按会话记住并优先。没有 merge-base（浅克隆、无关历史）时退回未提交改动。
3. **丢弃与回滚按范围区分。** 本会话范围保留 ADR-0044 的按文件、按 hunk 丢弃（基线写回、版本核对、`discard` 记录），不需要原生确认。未提交范围与提交视图提供 Git 回滚（工作区与 index 回到 HEAD，或反向应用一个未暂存的 hunk），回滚前由 Core 保存快照并经主进程原生确认（ADR-0085）。全部改动与单个提交范围只读：它们含已提交的内容，回滚到 HEAD 会让用户误以为已提交的改动也被撤销。
4. **Git diff 的形状。** Git 范围的每个文件给出 `GitFileChange`（路径、旧路径、状态、二进制、权限位、增删数、`FileDiff`），`FileDiff` 与 `piarc-diff` 同一协议形状，渲染进程用同一套 diff 组件。diff 由 `git diff` 生成并在 piarc-git 中解析；预算：超过 300 个文件、20,000 行或 patch 合计 1 MiB 时扣留 patch、按文件取（单文件上限 5 MiB）；面板增删合计超过 5,000 行时所有文件初始折叠。检查点范围仍用第 7.7 节的阈值。
5. **行内评论覆盖四种范围。** T42 的评论草稿增加所属范围（以及提交或基础 oid），只在同一范围重新定位；发出的消息写明范围。评论仍是渲染进程草稿（ADR-0060 不变）。
6. **工具身份不变。** 面板 id `changes`、命令 `changes.toggle`（Mod+Shift+D）、弹出窗口白名单与布局存储不变，标签改为"Git"，图标改为 `GitBranch`。右栏卡片在仓库内显示分支、领先落后与未提交合计，非仓库显示本会话合计。

## 备选方案

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| 纯 Git，去掉检查点视图 | 与参考版一致，概念更少 | 非 Git 目录没有改动视图；丢弃变成 `git restore`，会连带丢掉用户自己的未提交修改 | 否决（用户选择保留本会话） |
| 检查点为主，Git 作为另一个标签页 | 现有语义不变 | 与参考版的默认视图不一致，Bash 与用户的改动仍看不到 | 否决 |
| Git 范围也提供无确认的按 hunk 丢弃 | 操作快 | 回滚的是用户未提交的工作，渲染进程被注入时可静默删除 | 否决，改为快照 + 原生确认 |
| 面板 id 改为 `git` | 名称一致 | 用户自定义的快捷键失效，布局与弹出窗口、测试与威胁映射都要迁移 | 否决，只改标签 |

## 后果

- 正面：面板显示用户真正关心的改动（含 Bash 与手工修改、已提交但未合并的工作）；与参考版的默认体验一致；非 Git 目录不退化。
- 负面与代价：面板默认数字与本会话检查点合计不同，界面要写明当前范围；Git 范围对非 UTF-8 文件按 UTF-8 宽松解码显示。
- 需要配套做的事：ADR-0044 状态注明第 8 条被本 ADR 取代；架构 6.9、7.7、8.2 节改写；现有 L4 中工作区为 Git 仓库的夹具按新默认范围更新。

## 重新评估的触发条件

- 参考版的范围模型或默认范围变化；
- 需要在全部改动或单个提交范围上回滚（例如 G3 的 revert / reset）；
- 检查点与 Git 范围的数字差异在用户反馈中造成持续困惑。
