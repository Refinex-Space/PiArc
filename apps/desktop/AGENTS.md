# @piarc/desktop

Electron 客户端：主进程只做平台集成与转发，渲染进程只做呈现，业务逻辑在 Core 与 Agent Host（ADR-0013）。transcript 与 composer 的库选型见 ADR-0022。

## 命令

在仓库根目录执行。新机器或 `npm ci --ignore-scripts` 之后先下载 Electron 二进制：`node node_modules/electron/install.js`。

| `npm run start -w @piarc/desktop` | 开发服务器模式（`electron-forge start`，HMR，放宽的开发 CSP） |
| `npm run package:desktop` | 发布构建打包到 `apps/desktop/out/release/`（发布 fuses）；先构建该类型的 Core、Agent Host bundle，并下载校验内置 node、rg、fd |
| `npm run package:desktop -- --flavor development` | 同上，打包到 `out/development/`，同时生成 `.vite/` 生产构建；L4 前必须运行 |
| `npm run package:desktop -- --flavor release --arch x64 --make` | 指定架构并出安装包：macOS 为 `out/<flavor>/make/dmg/<arch>/*.dmg` 与 `make/zip/darwin/<arch>/*.zip`（x64 需 `rustup target add x86_64-apple-darwin`） |

## 结构

- `src/main/`（主进程，入口 `main.ts` 只做装配）、`src/preload/preload.ts`（`window.piarc`）、`src/renderer/`（React，入口 `main.tsx`）、`src/shared/`（三方共用的通道名与类型，`ipc.ts` 是 `PiarcApi` 的唯一定义）。四个 TS 工程分开：main 与 preload 没有 DOM 类型，renderer 没有 Node 类型；`e2e/` 是 L4。
- 安全基线（架构第 10.3 节）的实现位置与逐条对照见 `docs/spikes/S10-electron-security.md` 第 3 节；`src/main/security/` 与 `src/main/ipc/` 是入口。
- Core 只在 `src/main/core/` 加载与转发（ADR-0014）：`.node` 路径的唯一解析处是 `native-path.ts`；`router.ts` 按路由键转发事件批次；`terminal-ipc.ts` 管终端归属；`test-hooks.ts` 只在加载开发版 Core 时安装。`native/*.d.ts` 是 NAPI-RS 生成的 L1 快照，不手改。
- 渲染进程：transcript 在 `src/renderer/transcript/`（常量只在 `constants.ts`），Worker 在 `src/renderer/workers/`（ES module，受同一 CSP 约束），composer 在 `src/renderer/composer/`，终端在 `src/renderer/terminal/`（`vendor/ghostty-web/` 是 fork 的 MIT 代码，改动清单在其 README）。消息形状与守卫在各目录的 `protocol.ts`。
- 会话画廊 `#/session-gallery?section=<名称>`（`lab/SessionGallery.tsx`，分区与夹具在 `shared/transcript-lab.ts` 的 `GALLERY_SECTIONS` 与 `lab/fixtures/gallery.ts`）用正式的行组件、审批卡与 composer 渲染固定状态，只给评审截图用，和下面的原型页一样只在开发构建里。
- 原型页 `#/event-probe`、`#/transcript-lab`、`#/terminal-lab` 经 `globalThis.__piarc*` 给 L4 与基准用（类型在 `src/shared/`），只在开发构建里（`renderer/test-pages.tsx`，T45 起发布构建不带；终端原型页只能接测试钩子创建的终端）。
- 正式会话与原型共用 transcript 和 composer。行类型、历史窗口与滚动参数见 [transcript/AGENTS.md](src/renderer/transcript/AGENTS.md)，提及、附件与键盘约定见 [composer/AGENTS.md](src/renderer/composer/AGENTS.md)。
- 窗口（T18，ADR-0029）：主窗口的根是 `src/renderer/shell/Shell.tsx`（侧栏、主区、注册式右栏与面板区、对话框、提醒），设置是同一工作台里 `#/settings` 的视图（ADR-0101，`src/renderer/settings/SettingsLayer.tsx` 负责挂载、形态切换与焦点归还，`SettingsSurface.tsx` 是导航、搜索与页面；页面用 `settings/layout.tsx` 的 `SettingsSection`、`SettingsRow`、`SettingsItem`、`SettingsInfo` 排布，按项目区分的页面经 `settings/page-head.tsx` 的 `PageHeadActions` 把项目选择放到页头；设置打开期间 `app-shell` 带 `inert`）；两者共用 `src/renderer/app/app-context.tsx`（平台、偏好、翻译）与 `app.css`（只读令牌；元素级规则写在 `:root[data-app]` 之下，`main.tsx` 只给工作台设 `data-app`，原型页不受影响）。主进程的窗口、菜单、偏好、通知在 `src/main/app-shell.ts`、`menu.ts`、`preferences.ts`、`platform/attention.ts`、`platform/window-chrome.ts`；会话、工作区与信任命令在 `src/main/core/session-ipc.ts`。
- 注册点：会话详情栏与右侧工具分块 `registerPanel`（`src/renderer/shell/registry.ts`，area 为 `rail` 或 `tool`，没有注册内容的区域不渲染；右栏分节的操作经 `actions` 放在标题行末尾，用 `xs` 的 `IconButton`，与折叠箭头、拖动把手一样悬停或聚焦时显示，带 `data-attention` 的常显，卡片正文不放实体按钮）；设置页 `registerSettingsPage`（`src/renderer/settings/registry.ts`）；快捷键在 `src/shared/keybindings.ts` 的 `COMMANDS` 追加一行（id、`Mod` 记法默认键、标签消息 id），渲染进程的 `use-commands.ts` 与主进程菜单自动跟随；界面字符串在 `src/shared/i18n/en.ts` 与 `zh-CN.ts` 各加一条（类型检查保证两边键相同），用 `useT()`（渲染进程）或 `AppShell.t()`（主进程）。
- 打包在 `packaging/`（`Resources/agent-host/` 布局、分层签名、DMG maker、Velopack 绑定，架构第 5.6、13.2 节）；图标取 `design/brand/`，bundle id 与 AppUserModelID 取应用标识（`app-identity.mjs` 与 Rust 的定义由测试保持一致）。

## 不变量

- 新增 IPC 命令：在 `src/shared/ipc.ts` 加通道与 `PiarcApi` 成员，处理函数经 `registerHandler` 注册（ESLint 禁止直接 `ipcMain.handle`），参数当作 `unknown` 校验；同步更新 `e2e/preload.e2e.ts` 的键快照与 S10 报告。
- IPC 错误（I236）：Electron 的 `invoke` 只保留 `message`，`registerHandler` 经 `src/main/ipc/page-errors.ts` 把 Core 错误（`data.kind`）写成 `[piarc:<kind>] <原文>`（`src/shared/ipc-error.ts`）。页面显示失败原因一律用 `shell/errors.ts` 的 `reason()`：按 `error.kind.<kind>` 目录取当前语言的文案（`app/error-text.ts`，原文只作 `{detail}`），没有对应条目的类别与主进程自己的参数校验照原文；按类别分支用 `failureKind()`，不要匹配错误文字，也不要直接显示 `error.message`。新的 Core 错误类别要给用户看时在两份目录加 `error.kind.<kind>`。`e2e/ipc-errors.e2e.ts` 核对真实 Core 的错误带着类别到达页面。
- T21 的设置页 `#/settings/providers` 经 `providerSettings` 读取公开参数、内置提供商目录和凭据存在标志。密钥输入是写入专用的，`saveProvider` 将密钥与公开配置分开交给 Core；删除服务商及凭据由主进程原生确认。新会话的 `workspaceModels`、会话输入卡片的 `sessionModels` 都读 Agent Host 的可用模型和能力，切换前用 `previewModelSwitch` 取得代价，用户确认的模型与档位一起传入 `setSessionModel`。快捷键为 Mod+Shift+I（模型）和 Mod+Shift+E（推理强度）。
- T23 的设置页 `#/settings/permissions`（`settings/PermissionsPage.tsx`）经 `permissionRules`、`checkPermissionRule`、`updatePermissionRule`、`auditEvents`（`src/main/core/permissions-ipc.ts`）按来源列出、校验与编辑规则并筛选审计；新增或修改 allow 规则由主进程原生确认。跳过权限的开关写用户级 `/permissions/enableBypassPermissions`，模式菜单只在开启后列出它，选中时主进程再弹原生确认（`session-ipc.ts`）。审批卡的"总是允许"规则逐行可编辑（`rules`）。`PIARC_EVIDENCE_TASK=T23 npx playwright test -c apps/desktop/playwright.config.ts t23-permissions --project dev` 覆盖这些流程。
- T24 的设置页 `#/settings/diagnostics`（`settings/ConfigDiagnosticsPage.tsx`）经 `configDiagnostics` 读取 Core 的配置诊断：按文件列出加载状态、生效键（标量写明决定来源，列表为合并）、被覆盖键与覆盖来源、忽略键与原因、带行列的解析错误；订阅 `core/settings`，窗口重新获得焦点或页面恢复可见时也重新请求。诊断页可见时在上次请求结束 5 秒后复查，同一工作区的并发请求合并；关闭页面即停止。页面只读，Claude Code 的文件 PiArc 不写。L4 的 Core（`createForTests`）从 `<user data>/test-home` 读用户级 Claude Code 文件；`PIARC_EVIDENCE_TASK=T24 npx playwright test -c apps/desktop/playwright.config.ts t24-diagnostics --project dev` 覆盖这个页面。权限页同时列出 `.claude/` 两层与 `~/.claude/settings.json` 的规则（只读）。
- T25：`core/notices` 中 `type: "hook"` 的提示按 `id` 各占一条（至多 5 条，旧的让位），提示行用本地化标签写明事件（`notice.hookMessage`、`notice.hookError`），正文是 Core 给的详情；配置诊断页在文件之后列出 PiArc 不运行的 hooks 配置（报告的 `hooks`）。`PIARC_EVIDENCE_TASK=T25 npx playwright test -c apps/desktop/playwright.config.ts t25-hooks --project dev` 覆盖两者（hook 命令用 `printf`、`exit 1`，两个平台的 shell 都有）。
- T26（ADR-0042）：计划审批卡、提问表单与计划面板在 `src/renderer/approvals/`（见其 AGENTS.md），任务卡与下一步建议在 `transcript/rows/harness.tsx`，右栏任务卡片与停靠的计划面板经 `shell/harness-panels.tsx` 注册。`answerApproval` 的 IPC 校验接受 `mode`、`comments`、`answers`（形状与大小，语义由 Core 查）。`PIARC_EVIDENCE_TASK=T26 npx playwright test -c apps/desktop/playwright.config.ts t26-harness --project dev` 覆盖这些流程。

## 易错点

- L4 夹具给应用设 `PIARC_TEST_MEMORY_KEYCHAIN=1`：开发构建的 Core 改用 `createForTests`，保险箱主密钥放在内存。每次重新打包都是新的 ad-hoc 签名，打包形态读钥匙串里的 `cn.piarc.desktop.credential-vault` 时 macOS 会弹窗要登录密码，会话创建会一直等它（T18 实测）。发布构建没有 `createForTests`，这个开关不起作用；真实钥匙串的验证在 `piarc-secrets` 的 `system_store` 测试与 S6 的 `keychainProbe`。
- T18 的 L4 依赖窗口真的在前台（标记已读只在前台发生）：测试里用 `e2e/sessions.ts` 的 `focusMain(app)`（`app.focus({ steal: true })`），不要假设 Playwright 启动的窗口有焦点。原生对话框用 `stubFolderDialog`、`stubMessageBox` 替换，Playwright 点不到它们。
- macOS 上页面截图把半透明的侧栏合成在白底上，看不到 vibrancy：评审截图用 `screencapture -l <窗口号>`（`BrowserWindow.getMediaSourceId()` 的数字部分，见 `e2e/t18-review.e2e.ts`）。运行 L4 的终端要有系统设置中的“屏幕录制”权限，否则 `t18-review` 报 `could not create image from window`。
- 新建会话时乐观消息用 `flushSync` 立即提交：创建失败可能在下一次渲染之前就返回。
- `useState` 的初始化函数不要有副作用（例如读完即删 sessionStorage）：页面首次渲染可能挂起，React 丢弃这次渲染后会再调用一次（`settings/browser-import-target.ts` 的 `useImportTarget` 先读、提交后再删）。
- composer 的附件只有一个货架（`composer-attachments`，网格区域 `shelf`）：再加一个同区域的容器会与它重叠。
- 输入卡片的操作行控件写颜色时要高过 `:root[data-app] button { color: inherit }`（特异度 0,2,1）：只写两个类的规则会被它盖掉，例如模型名用 `.composer-trail .choice-button.composer-model`。
- L4 在无人值守的 Mac 上：被测应用退出后系统可能没有任何前台应用，下一个实例的 `app.focus({ steal: true })` 拿不到焦点，`focusMain` 全部超时；先让一个应用（如 Finder）在前台再跑。
- `dev` 形态跑的是上次打包生成的 `.vite/`：改了 `src/` 要重新 `package:desktop -- --flavor development`；`electron-forge start` 会清掉 `.vite/renderer`，之后 L4 报 "Production bundle not found"。
- Node 的 `URL` 不认识 Chromium 注册的标准协议：`new URL('app://piarc/').origin` 是 `'null'`。
- 导航被取消后 Playwright 定位器会一直等导航完成：拦截之后用 `page.evaluate` 检查，会触发导航的点击用 `page.mouse.click`。
- 发布构建拒绝 Chromium 的 `--remote-debugging-port`（没有对应 fuse，T45 起主进程在 `ready` 前移除并退出，I10）；开发构建保留，Playwright 依赖它。
- 应用启动早期打印的日志行，L4 夹具接上 stdout 之前就被读走了；要断言启动状态，用测试钩子读主进程状态，不等日志。
- `monitorEventLoopDelay` 记录的是两次采样之间的完整间隔，每个值都含采样间隔（钩子用 1 ms）；比较预算时按原始值算偏保守。Windows 默认计时器粒度约 15.6 ms，1 ms 的采样实际约 15.6 ms 一次，空闲的 Node 就是 p50 15.6 ms、p99 16.6 ms（S2 报告第 8 节）：在 Windows 上要和同机空闲基线一起看。
- 基准与 L4 都要开发版 Core：发布版没有测试钩子，`expectTestHooks` 会直接报错提示重新打开发构建。
- Electron 的 `contentTracing` 输出 protobuf 追踪；要 JSON 就用 CDP 的 `Tracing.start`（`streamFormat: 'json'`），S1 基准就是这样做的。
- 帧时间的口径：rAF 间隔与 `AnimationFrame`（LoAF 口径）在 60 Hz 屏上空闲时也约 16.7 ms，不能拿来和"p99 ≤ 16 ms"比；S1 基准用两次 `BeginMainThreadFrame` 之间主线程任务的总耗时（每帧工作量）。
- 复制相关的 L4 会写系统剪贴板：用例经 `withSavedClipboard` 读出原内容、结束后写回（只恢复文本）。Windows 上 Chromium 以 CRLF 写纯文本，`readClipboard` 已规范为 LF。
- Windows 上的系统通知：Electron 先发 `show`，系统拒绝（未经安装、没有带 AUMID 的开始菜单快捷方式，或用户关了通知）时再发 `failed`；以最后一个事件为准。
- Windows 不让 Playwright 启动的窗口稳定留在前台（W1 实机与 CI 都出现）：依赖"窗口在前台"的断言要容忍窗口在后台时多出的提醒；遍历窗口时同时排除 `webContents.isDestroyed()` 的窗口（关闭中的窗口先销毁 `webContents`）。`t18-review` 在 Windows 上截取窗口所在的屏幕区域（Mica 与窗口控件由系统绘制），截取时临时置顶。
- 用例按界面文案断言时同时匹配英文与简体中文（界面语言跟随系统，W1 的机器是中文）。
- Windows 的经典滚动条占约 12 px 宽度：transcript 出现或去掉滚动条会改变列表宽度，见 `src/renderer/transcript/AGENTS.md`。
- L4 里 `app.process().pid` 不一定是主进程（Windows 上可能是 Playwright 前面的启动器）：要主进程 pid 用 `app.evaluate(() => process.pid)`。
- 从 Node 调 PowerShell 时关掉它的 stdin（`stdio: ['ignore', …]`），否则命令打印完结果还会一直等 stdin。
- ProseMirror 自己在合成期间不分发按键，所以只测合成中的按键测不出守卫是否生效；`composer.e2e.ts` 另有"合成开始前到达的 229 按键"和"合成文本恰为 `@`、`/`"两类用例，去掉守卫时它们会失败。
- 页面处理按键之后，经事件 MessagePort 投来的消息要到下一帧的 rAF 之后才被处理（`invoke` 的回复不受影响）：所以终端帧作为 `requestTerminalFrame` 的返回值送达，不要改回事件端口（ADR-0023，S7 报告第 5.2 节）。
- 终端 L4（`terminal.e2e.ts`、`terminal-tui.e2e.ts`）按平台选程序：macOS 用 `/bin/sh`、`cat`、`vim`、`top`；Windows 用 cmd（`PROMPT=$$$S`）、PowerShell、Git 自带的 vim（由 `git --exec-path` 找到）与 `e2e/programs/show-keys.ts`（Node 直接运行 `.ts`）。ConPTY 下 conhost 会重新编码按键，Windows 版的按键用例只断言按键到达程序。 面板（T34）：终端只认真实输入：L4 用 Playwright 的键盘、鼠标或 CDP 输入驱动面板，页面里直接调写入命令会被拒绝；最小化窗口的 rAF 仍在跑，按帧工作的视图看 `visibility` 应用事件（`renderer/app/window-visibility.ts`）；axe 要 `setLegacyMode(true)`。
- 不要在 `postPackage` 之前把内置 node 放进 bundle：fuses 插件与 `resealElectron` 的 `--deep` 会把它改成 ad-hoc 签名。新增随包的 Mach-O 文件放在 Resources 下即可，`signResourcesAndBundle` 会扫描签名；要保留原签名的目录加进 `keepSigned`。
- 本机 Gatekeeper 评估被关闭时（`spctl --status` 为 `assessments disabled`），`spctl --assess` 一律显示 accepted，不能作为首次打开的证据；首次运行检查要在开启 Gatekeeper 的机器上做。
- MCP 夹具要先 `npm pack` 再经 `npx --package <tgz>` 启动：`npx <目录>` 会链接目录并 chmod 其中的 bin，在 Agent Host 的 Seatbelt 下被拒绝（真实 MCP 包来自 registry 的 tarball，不受影响）。
- 更换虚拟列表时要重测内容增长到贴底的帧时序。行变高与 `TranscriptList` 更新 sizer 尺寸可能分两次提交，回归用例逐帧检查离底距离（ADR-0022、ADR-0030）。
